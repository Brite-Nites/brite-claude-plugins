### Alternatives Considered

1. **Option A — Remove "Add co-owner" from SQ3** *(chosen)*. Smallest surface; spec-faithful to BC-5810 § 2.2; mirrors BC-5864/5865 STOP-block citation shape; no new mutation type. Option 3 "Mark unassigned" added to match BC-5810 § 2.2 verbatim (not an extension).

### Reason (why chosen)

BC-5810 § 2.2 SQ3 already defined the three escape paths (keep / reassign / unassigned). The W17 improvisation invented a fourth lane with no data-model backing. Option A restores spec fidelity while the BC-5866 class-fix contract provides the enforcement mechanism — no new primitive needed, only pattern re-application.

### Sub-learnings (worth one line each)

1. **`###` subsections need their own gate-respect reminder.** The linter's `_walk_sections` walks `##` AND `###` as independent sections; parent-`##` comments don't cascade into child `###`. First hit on this session because BC-5864/5865 added inline prose to existing `##` bodies rather than introducing new subsections. Discovered mid-exec: first linter run errored `§ 4.1 SQ3 option lock: AskUserQuestion at line 118 without gate-respect reminder`. Fix: add a one-line `<!-- gate-respect: ... -->` directly under any `###` that mentions `AskUserQuestion`.
2. **Plan-drift spans exec-time AND review-time.** This session logged three distinct departures: (a) § 4.1 gate-respect reminder added mid-exec, (b) "Mark unassigned" option-count delta noticed mid-review, (c) simplify-pass regex consolidation (commit `c7255dd`) also caught mid-review. BC-5864/5865 precedent captured exec-time departures only; BC-5872 extends the pattern — Departures section captures *every* deviation regardless of phase, and the review-loop tidy-up commit is the idiomatic place to add them retroactively.
3. **Simplify catches real behavior improvements.** Collapsing `add\s+co-owner` + `\bco-owner(?:s|ship)?\b` into `\b(?:add\s+)?co-owner(?:s|ship)?\b` changed the linter output from 2 ERROR rows per violation to 1 — cleaner, same rejection semantics. Reinforces the BC-5866 class memory entry *"simplify catches real bugs disguised as style nits"* — third session to confirm it.
4. **Review-pass P3 tidy-up budget scales with PR size.** On a ~190-line PR with 3 P3 findings, all confirmed by Step 6 validation, applying the fixes took ~8 lines and one commit. Worth applying even though command rules say P3s are FYI-only — keeps Departures section honest, regex style symmetric, and audit trail clean. Cost/benefit favors apply under ~200-line PRs.
