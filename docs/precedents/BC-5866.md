**Confidence:** 8/10
**Tags:** pattern-choice, cross-skill-contract, structural-linter, cadence-plugin, class-bug-fix
**PR:** [#169](https://github.com/Brite-Nites/brite-claude-plugins/pull/169)
**Precedent Referenced:** BC-5790 (first-of-N locks template), BC-5902 (context-pressure class fix), `plugins/workflows/skills/_shared/*.md` (shared-contract precedent in workflows plugin)

## Decision

For a bug-class that affects multiple skills inside one plugin (here: silent gate-deviation in any Cadence skill after the user picked a specific option), codify the fix as a three-part durable pattern rather than patching each instance inline:

1. **Contract file** at `plugins/<plugin>/skills/_shared/<contract>.md` — verbatim rule, rationale, application clauses, tripwire list. Standalone markdown, not a SKILL.md.
2. **Per-section markers** at each gate-rendering surface — one `<!-- <contract>: -->` HTML comment at the top of each `## § N` section that renders the relevant tool call. Locality-of-concern, one per section (not one per call).
3. **Structural linter** at `scripts/_lib/lint_<contract>.py` — Python stdlib only, emits `OK:`/`ERROR:` lines consumed by `scripts/validate.sh`, mirrors `lint_hooks.py` precedent. Wired into validate.sh under a new `## N.N <Name>` block, guarded by `plugin_name` or a convention file (e.g. presence of the contract file) if the contract is plugin-scoped.

Specific instances of the bug (BC-5864 project-level triage gate, BC-5865 condensed-prompt shortcut) are fixed separately and become mechanical applications of the contract after it lands.

## Key alternatives considered

1. **Inline-only fix for BC-5864 + BC-5865, no separate class fix.** The violating pattern was a one-off in sprint-scoping; patch it, move on. **Rejected.** BC-5866's issue body makes the class-vs-instance distinction explicit, and the W17 dogfood already shows the same failure mode showing up differently across skills. Two instances in one phase is prima facie evidence the class fix has value. The cost is small (~1 day of work) vs. the recurrence cost in a growing plugin.
2. **Contract lives in `docs/designs/` as a one-shot design doc.** **Rejected.** `docs/designs/` is for historical decisions (e.g. `cadence-orchestration.md`); `_shared/` is for living contracts. Distinction matters: consumers link to `_shared/` files at runtime (relative path from SKILL.md), and contracts evolve alongside the skills they govern. `plugins/workflows/skills/_shared/` is the established precedent.
3. **Single top-of-file header section in each consumer, no per-section markers.** **Rejected.** A single header works for human readers but gives the linter no anchor point to enforce "every multi-option gate has a nearby reminder." Per-section markers are the CI-enforceable surface; the top-level header is the human-readable one. Both are needed.
4. **One comment per individual `AskUserQuestion` call (per-question, not per-section).** **Rejected by contract Rule 2.** A section that asks 5 sequential questions gets one reminder at the top; the linter enforces section-level coverage, not per-call. Keeps the diff light and the markdown readable. If the linter ever needs call-level granularity, that's a follow-up, not v1.
5. **Plugin-specific linter filename vs. generic.** The linter landed as `lint_cadence_gates.py` — encoding the first-adopter plugin name. Architecture-reviewer flagged it as P2 (filename encodes one plugin but the logic is plugin-agnostic). Validated by Sonnet → **downgraded to P3**: naming-after-first-adopter is idiomatic here (`lint_hooks.py` was never renamed for generality), 4 external references would need coordinated updates on rename, and there is zero second-adopter pressure today. Marketing's `/marketing:launch-campaign` doesn't use the contract; revops commands don't either. Rename the day a second plugin opts in — not before.

## Secondary observations

- **Simplify-pass caught a real bug disguised as a style nit.** The initial linter's repo-root detection walked `plugin_dir` up 3 parents (one too far) and produced output like `ERROR:bc-5866/plugins/cadence/...`. Quality agent flagged the loop as "over-engineered"; fixing it to `(plugin_dir / "../..").resolve()` removed the `bc-5866/` prefix artifact from validator output. Simplify-pass findings are not all style — some are latent bugs masquerading as cleanup. Don't skip the simplify step on small PRs.
- **Linter false-positive taxonomy for markdown-embedded tool-call detection.** Three classes need explicit handling: (1) fenced code blocks containing example tool-calls (triple-backtick AND tilde fences, CommonMark supports both), (2) blockquoted prompt templates like Gate #3's user-facing preview that quotes markdown including the tool name, (3) prose mentions with negation or nominal usage (`no AskUserQuestion fires`, `the AskUserQuestion convention`, `Three AskUserQuestion gates`). Missing any class produces FP-laden output that erodes linter credibility. Solution: fence-state toggle inside the per-section body scan, blockquote-line skip, and prose-pattern regex with hedge+nominal filters. Took ~3 iterations to nail down.
- **Triage-agent TRIVIAL verdict overridden — correct call.** diff-triage agent classified the PR as TRIVIAL because the visible diff-stat is 59 lines of documentation. The ~276-line untracked linter was treated as "validation infrastructure, not behavior." Orchestrator overrode to NON-TRIVIAL; the thorough review surfaced 3 P2s all in the new linter. Rule: **any new runtime code file >150 lines is non-trivial even if the rest of the diff is docs.** diff-triage is a Haiku agent briefed on a stat summary; it cannot inspect new-file contents, so its trivial-verdict on mixed doc+code PRs is unreliable.
- **CDR-compliance-reviewer skip on Context7 quota.** Session started with Context7 MCP quota-exhausted. The reviewer correctly refused to substitute `gh api` for the CDR INDEX read (the agent's loading protocol caps confidence at 0 when CDR identity is invented from unstructured content). Skip was graceful per its own rules. No CDR coverage this PR — re-run once quota resets if a CDR conflict is suspected.
- **Session override of diff-triage TRIVIAL paid off.** The P2s caught included a UnicodeDecodeError that aborts validate.sh under `set -e` — a real CI break risk. Had the orchestrator honored TRIVIAL, all 3 P2s would have shipped silently and been found by the first author who documented an AskUserQuestion example inside a fenced code block.
- **Post-ship re-review finds bugs pre-ship thorough-mode missed, on the same file.** After ship, a user-requested thorough re-review (overriding a second TRIVIAL diff-triage verdict) surfaced a 4th real bug in the linter the first thorough pass missed: `GATE_RESPECT_COMMENT_RE.search` ran on raw body lines without fence filtering, asymmetric with call-site detection that uses `_iter_active_lines`. Fenced `gate-respect:` examples would false-pass. Plus a cosmetic `§§` double-prefix in ERROR output and a missing grep-findable TODO for the deferred plugin-name hardcode. BC-5795 class: **post-ship review is not redundant**; the reviewer's lens shifts once the pre-ship verdict is known, and different bugs surface. Defer cleanups cost merges-open-longer, not repeats-of-reviews. Shipped as commit `e4bf56a` + `48ddbe5` (gitignore chore for the __pycache__ artifact).

## Rule derived

**For a recurring bug class in one plugin, codify the fix as a three-part durable contract instead of patching each instance.**

Template:
1. Contract markdown at `plugins/<plugin>/skills/_shared/<rule>.md` — verbatim rule + application + tripwires + references. Not a SKILL.md.
2. Per-section marker comment (`<!-- <rule>: -->`) at the top of each consumer section that exhibits the pattern. One per `## § N`, not per call.
3. Structural linter at `scripts/_lib/lint_<rule>.py` (Python stdlib, OK:/ERROR: emission), wired into `scripts/validate.sh` under a new numbered sub-section. Linter must handle three markdown false-positive classes: fenced code blocks (both ``` and ~~~), blockquotes, prose mentions with hedge/nominal framing.

**Sub-rule:** Orchestrator must override a diff-triage TRIVIAL verdict when the PR introduces new runtime code files larger than ~150 lines. diff-triage cannot read new-file bodies; its verdict on mixed doc+code PRs is unreliable for untracked additions.

**Sub-rule:** In plugin-specific tooling, filename-encodes-first-adopter (e.g. `lint_cadence_gates.py`) is acceptable v1; rename only when a second plugin actually opts in. Speculative generalization for one-adopter utilities incurs naming-debt churn without benefit.

Template inheritable by any future class-fix in any Brite plugin (marketing, revops, workflows) when a recurring pattern needs enforcement. First application: Cadence. Second application to watch for: marketing launch-campaign if multi-phase AskUserQuestion gates ever drift there.
