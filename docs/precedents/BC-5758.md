# BC-5758: Later-locked research decision supersedes earlier-issue scope wording

**Date:** 2026-04-19
**Category:** scope-change
**Confidence:** 8/10

## Decision

When a later research issue (BC-5811) ships a locked decision that contradicts a scope detail in an already-filed downstream issue (BC-5758), the later decision wins. Flag the departure at the Plan checkpoint, get explicit approval, and call it out in both the commit message and PR description. Do not treat earlier issue bodies as frozen specs when later-dated locked design docs supersede them.

## Context

BC-5758 (Cadence scaffold) was filed with scope wording: `.mcp.json` registers the Linear MCP server. BC-5811 (Cadence GitHub integration research) shipped after BC-5758 was filed and locked `.mcp.json` to `{"mcpServers": {}}` because Cadence consumes Linear via the workflows plugin's registration — duplicate registration triggers the documented "Tool not found" gotcha. BC-5758's wording predates BC-5811's decision.

Without an explicit handling rule, agents have two unsatisfying options: (a) honor BC-5758 literally and register Linear, knowing it breaks tooling; (b) silently deviate from BC-5758's scope with no approval trail. Both harm downstream auditability.

## Alternatives Considered

1. **Honor earlier issue wording literally.** Rejected: introduces a known tooling break (Linear MCP duplicate registration), and the later-dated design doc is the better-informed source.
2. **Silently deviate from earlier scope in the PR.** Rejected: no approval trail; reviewers can't distinguish an authorized departure from a mistake.
3. **Flag at Plan checkpoint, get explicit approval, record in commit + PR (chosen).** Preserves decision authority with the user, leaves an auditable trail in three locations (Linear plan comment, commit body, PR description), and keeps the shipped artifact consistent with the later locked decision.

## Outcome

Cadence scaffold ships with `.mcp.json = {"mcpServers": {}}`. The departure is documented in PR #135 description under a "Departure from BC-5758 original scope" subheading, in the commit body, and in the Linear plan comment. Downstream phase issues (BC-5759–5762) inherit the empty-registration convention without needing to re-litigate.

**Reusable beyond this case.** This precedent applies whenever a plugin milestone front-loads research/design issues that land before their own scaffold/implementation issues are picked up — any time Research-issue-N locks a decision that contradicts Impl-issue-M's pre-filed wording, the same Plan-checkpoint approval path applies.
