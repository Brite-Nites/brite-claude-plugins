## Task 4 — Linear MCP `create_attachment` is for file uploads, not URL refs; PR auto-linking is the path

| Field | Value |
|---|---|
| **Decision** | Don't call `mcp__plugin_workflows_linear-server__create_attachment` to attach a PR URL — its signature expects `base64Content` + `filename` + `contentType`. Linear's GitHub integration auto-creates URL attachments on `save_comment` when the comment body contains a PR URL (visible in `save_issue` response's `attachments[]`). |
| **Category** | bug-resolution |
| **Confidence** | 7/10 |
| **Precedent Referenced** | none (1st surface) |

**Inputs**
- MCP error: `create_attachment` requires `issue`, `base64Content`, `filename`, `contentType`; rejected `issueId`, `url`
- BC-6955 `save_issue` response: `attachments[0].url` already populated with PR #263 link from prior `save_comment` body
- Existing precedent for URL attachment via comment body: Linear's GitHub integration handles it

**Alternatives Considered**
1. **Chosen** — Skip `create_attachment` entirely; rely on Linear's GitHub-integration auto-linking from the PR URL in the `save_comment` body.
2. Rejected — Base64-encode a JSON blob with the URL and pass as `base64Content` to satisfy the schema. Wastes work; doesn't produce the right attachment shape (would render as a downloadable blob, not a clickable link).
3. Rejected — Fall back to the legacy attachment-creation endpoint via `call_api` raw passthrough. Unnecessary; GitHub integration is the documented path.

**Outcome**
- `/workflows:ship` step 3 succeeded with `save_issue` + `save_comment` only; PR attached automatically
- Memory update: add `gotcha_linear_create_attachment_url_vs_file.md` so future ship cycles don't repeat the wrong call

**Generalization**: Linear MCP's `create_attachment` is for binary file uploads (screenshots, PDFs, etc.), not URL bookmarks. URL bookmarks come via the GitHub integration's auto-link on commented PR URLs. If a non-PR URL needs attaching, use Linear's UI or the GitHub-app-equivalent for the target service; do NOT call `create_attachment` with `issueId` + `url`.
