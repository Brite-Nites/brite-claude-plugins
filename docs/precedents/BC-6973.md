## task-3 — NEW PATTERN: iter-2 catches Q-canon fabrication in iter-1's mechanical fold-in; cdr-compliance-reviewer is the only reliable canon-verification gate

Both fabrications were caught at iter-2 by the cdr-compliance-reviewer agent with confidence 10/10 + 9/10 respectively. The pattern: **when iter-N mechanically applies a fix involving citations to Q-canon (or any external locked source), iter-(N+1)'s cdr-compliance pass catches fabricated citations that the in-flow plan didn't verify**. **Category:** pattern-choice

**Confidence:** 9/10

**Inputs:**
- iter-1 fix for the `<flow-id>` derivation problem (P2 from quality-reviewer) introduced this prose at Step 4 item 2: "Parse the `flow-id:<slug>` label into `<flow-id>` (per Q24 mod 3 the discipline-child carries this label directly — no parent fetch needed for the slug). [...] If the label is absent, fall back to parsing the parent issue's title (sub-flow parents are titled `<DOMAIN>-NN: ...` per Q22 template)."
- iter-2 cdr-compliance-reviewer ran a grep + read against `project_fda_plugin_interview.md` for the cited Q-locks and discovered:

The fabrication would have forced every consumer of the discipline-child label vocabulary to either honor or reject a non-canonical label, bypassing the Q-amendment audit-trail discipline.

No parent fetch needed for the slug derivation; the parent fetch stays scoped to L3 summary extraction only. Parallel batch in Step 4 item 3 preserved on all paths.

- Independent post-PR reviewer confirmed no `flow-id:<slug>` label fabrication remains in the merged file.

**Alternatives Considered:**
