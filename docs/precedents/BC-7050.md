## task-1 — Verbatim-port discipline includes parser tolerance, not just request shape

**Decision:** When porting an HTTP-client wrapper from an upstream package, the verbatim-port goal extends to the parser's *tolerance behavior* (silent-skip on malformed lines, default values for missing fields, etc.), not just the request URL/headers/method. The first BC-7050 commit mirrored the upstream `spider-cloud-mcp@2.1.1` request shape (endpoint, Content-Type, response-format) but used a bare `[json.loads(line) for line in ...]` list comprehension that would raise on a single malformed JSONL line — diverging from the upstream's `parseJsonlStream` (`dist/api.js:50-55`) which explicitly try/catch-skips per line. The fold-in commit replaced the list-comp with the equivalent tolerant loop. Lesson: when the canonical impl handles a class of partial/malformed input gracefully, mirror that handling — don't assume the happy path is the contract.

**Category:** pattern-choice

**Confidence:** 8/10

**Inputs:**
- `/tmp/bc7050-spider/package/dist/api.js:23-63` — `parseJsonlStream` impl (try/catch per `JSON.parse`)
- `plugins/marketing/scripts/tam-map/spider_crawl.py:51-58` (post-fold-in) — tolerant per-line loop
- `/workflows:review thorough` — code-reviewer P3 [7] + security-reviewer P3 [5] both flagged the divergence; independent validator CONFIRMED both

**Alternatives Considered:**
1. (Chosen) Replace list comprehension with try/except-per-line loop, mirroring upstream MCP. Reason: verbatim-port discipline includes tolerance behavior; one bad line shouldn't abort the whole domain crawl when upstream tolerates it.
2. Keep the list comprehension and rely on outer `except Exception` to catch JSONDecodeError. Rejected — the outer catch loses ALL pages for that domain when one line is malformed; upstream's per-line skip preserves the rest.
3. Switch to `aiohttp`'s `r.content` chunked async iterator + line buffer to mirror MCP's chunk-streaming exactly. Rejected — MCP's stream-vs-buffer choice is an internal optimization, not a contract; the tolerance-on-bad-line IS the contract.

**Precedent Referenced:**

- BC-7011 (endpoint-drift fixes in `aiark-mcp.js`) — parallel class (REST contract drift) but didn't surface a tolerance-vs-happy-path question because the fix was URL/auth, not response-parsing
- None — first time encountering "verbatim-port discipline includes parser tolerance" as an explicit principle
