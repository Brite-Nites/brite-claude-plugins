## task-1 — Cross-repo URL slugs in plugin docs need live `gh api`-verification at authorship; review agents see strings, not resources

**Decision:** When a CLAUDE.md / reference doc / handbook page cites cross-repo URLs (handbook decision records, operating-standards pages, about-handbook templates, sibling-repo files), the authoring discipline must include `gh api repos/<owner>/<repo>/contents/<path>` for each URL at write-time — not later, not as a follow-up, not "spell-check it". The /workflows:review pipeline as currently constructed (code-reviewer + security-reviewer + performance-reviewer + cdr-compliance-reviewer × 3 iterations + a simplify pass + per-finding validator subagents) does NOT walk URLs; it treats them as opaque strings. The diff-triage Haiku, the 4 review agents, the 3 simplify agents, and the validator subagents collectively performed ~30 read passes over the file across 3 iterations and missed a 404 on `CDR-014-phase-pattern.md` (actual file: `CDR-014-milestone-standards.md`). The independent post-PR reviewer caught it on first read because its prompt explicitly directed `gh api`-verification of each URL — a different verification protocol, not a smarter reviewer. The cdr-compliance-reviewer in particular checked CDR-023's URL and verified the `Brite-Nites/handbook` subdirectory canon was applied (Q33/Q34 amendment 2 compliance) but did NOT verify that the cited slug for CDR-014 resolved — that check was scoped to "is this the right repo/branch convention," not "does this file exist." Three lessons compound:

1. **The verification protocol matters more than the reviewer's intelligence.** A high-confidence cdr-compliance-reviewer + Opus-validator pass returned "0 P1/P2/P3, compliant" at iter-3 while a P1 sat in the file the entire time. The reviewer's prompt said "spot-check Q-numbers, verify handbook canon, check for CDRs that should be cited but aren't." None of those checks resolve a slug.
2. **Cross-repo URL drift survives every internal review iteration.** The drift wasn't introduced in iter-2 or iter-3 — it was in the file from the initial write (the slug I chose matched the parenthetical title `(Phase Pattern)` rather than the actual filename `milestone-standards.md`). It survived 3 review iterations + a simplify pass because no internal review touched the network.
3. **Internal-to-this-repo cite drift (BC-6955-rework task-1) and cross-repo URL drift (this task) are sibling classes with the same root cause.** Both rate "factually correct" under string-comparison review; both require a ground-truth-fetch verification step to detect. BC-6955-rework's fix was per-cite verify against the source file (in-repo line read). This task's fix is per-URL `gh api` resolve. The unifying meta-pattern: **any cross-document reference (line number, URL slug, anchor link, file path) needs ground-truth fetch at authorship — string match against design-rationale is insufficient.**

The fix: encode the discipline into the `/workflows:review` step 4 prompt for cdr-compliance-reviewer (and any reviewer that touches CLAUDE.md / doc files) — add an explicit "for each external URL in the diff, resolve via `gh api` and report 404s as P1" check. The independent post-PR reviewer already does this; promoting that protocol to an inside-the-loop reviewer would catch URL drift before push.

**Alternatives Considered:**
1. (Chosen) Promote `gh api` URL verification into the cdr-compliance-reviewer prompt (Step 4 of /workflows:review). Reason: cdr-compliance-reviewer already specializes in handbook/CDR canon; URL slug verification is a natural extension. Single-prompt change, broad coverage.
2. Add a separate `link-checker` agent to Tier 3 of /workflows:review. Rejected — adds an agent slot, parallel-fans the cost, and overlaps cdr-compliance-reviewer's domain.
3. Build a CI check that walks every URL in changed `*.md` files with `gh api`. Rejected for now — moves verification from author-time to push-time; agent in /workflows:review catches it pre-push. CI-side check is a v2 candidate if author-time discipline drifts.
4. Tighten the diff-triage rule: any `*/CLAUDE.md` change with new URLs defaults to NON-TRIVIAL with mandatory URL walk. Partial — already partial today (CLAUDE.md auto-classified NON-TRIVIAL), but the URL-walk-on-CLAUDE.md is the missing piece.
5. Document the discipline in the plugin-internal CLAUDE.md itself ("when citing handbook URLs, `gh api`-verify slugs at authorship") and trust it as a maintainer convention. Rejected as a sole fix — relies on every future author reading it; agent-side enforcement is the load-bearing layer.
