## Decision

Ship BC-5864 (project-level triage gate) and BC-5865 (condensed-prompt shortcut) as one bundled PR that mechanically applies the BC-5866 class-fix template. Adopt the following v1 discipline for applying shared contracts:

1. **Extend the shared artifact, don't duplicate it.** The class-fix contract already exists (`plugins/cadence/skills/_shared/gate-respect.md`) and the linter already enforces per-section reminder coverage. Instance fixes add two surfaces: (a) explicit STOP blocks in the consumer skill body naming the specific W17 improvisation phrases verbatim, (b) `FORBIDDEN_PHRASE_PATTERNS` regex entries in the linter so authorizing re-introduction fails CI with ticket attribution. No new shared file, no new linter.
2. **Exemption shape mirrors existing intent filters.** `FORBIDDEN_EXEMPT_PATTERNS` uses a two-regex shape matching `PROSE_PATTERNS`: italic-quote (`\*"..."*`) for per-bullet citation + negation cues (`\b(?:no|do not|never|banned|forbidden|improvisation)\b`) for surrounding-prose discussion. Line-level, not section-level — the plan originally prescribed a `FORBIDDEN_PHRASE_EXEMPT_SECTION_PREFIXES` allowlist but that was unnecessary because `_collect_targets` doesn't glob `_shared/gate-respect.md` (where Tripwires lives), so section-level exemption was solving a non-problem. Ship the simpler line-level design; document the plan-vs-implementation drift in the plan file's "Departures from plan" section.
3. **Bundle siblings when they share a file.** BC-5864 + BC-5865 both edit `sprint-scoping/SKILL.md` and both extend `FORBIDDEN_PHRASE_PATTERNS`. One PR, one review surface, one commit-trail makes review easier than two back-to-back PRs touching identical lines.

## Key alternatives considered

1. **Two separate PRs (one per issue).** **Rejected.** Same file (`sprint-scoping/SKILL.md`), same linter surface (`FORBIDDEN_PHRASE_PATTERNS`), identical review agents. Two PRs would churn the same review pipeline twice with near-identical diffs. Bundling mirrors how BC-5866 shipped both the class contract + the first-instance linter in one PR.
2. **Text-hardening only; skip linter extension.** **Rejected.** The W17 dogfood showed that STOP-block prose alone is not strong enough — the runtime agent improvised "pragmatic" / "condensed-prompt" language that the existing spec negations ("no batching") didn't literally match. Linter extension makes regression detection mechanical.
3. **Section-level exempt (per original plan).** **Rejected during execution.** Saw that `_collect_targets` doesn't reach `_shared/gate-respect.md` → section-level Tripwires exemption is unneeded. Line-level exemption (italic-quote + negation cue) is simpler, mirrors `PROSE_PATTERNS` shape, and covers every STOP-block construction shipped. Plan-vs-implementation drift captured in docs/plans/BC-5864-BC-5865-plan.md.
4. **Defer linter extension to BC-5874 third dogfood.** **Rejected.** BC-5874 is the E2E runtime verification; linter extension is a structural/static check. Coupling them delays the structural guardrail unnecessarily — and the dogfood might not surface a linter regression at all.

## Secondary observations

- **Worktree absolute-path gotcha bit twice.** `gotcha_write_tool_worktree_path` memory entry fired during (a) the first § 2 Edit call (used primary-path instead of `.claude/worktrees/.../` prefix), and (b) the plan-file Write call. Both recovered via `git restore` in the primary checkout. Pattern: the Read tool tolerates either path (it resolves to the same file), so the habit of using the primary absolute path sticks; but Write/Edit are destructive and land literally where you point them. Mitigation for future sessions: always prefix the worktree path, especially for the **first** Write/Edit in a worktree. The gotcha entry stays load-bearing.
- **Simplify-pass catches real bugs disguised as style nits (BC-5866 class re-confirmed).** Three simplify fixes applied, all genuine improvements:
  1. `do NOT` in `FORBIDDEN_EXEMPT_PATTERNS` was redundant because the regex is `re.IGNORECASE`. Pure style → no behavior change.
  2. `shortcut` and `W17 dogfood` as exempt cues were **too-loose** — "W17 dogfood" as a substring would false-exempt ANY line mentioning the dogfood origin, including a line that cites the dogfood while authorizing the pattern. Quality agent caught this correctly; removing them tightened the contract without breaking any current STOP block.
  3. Inverting the exempt-check order (lazy-evaluate only on first forbidden-phrase match) saves 2 regex searches per clean line while preserving multi-ticket attribution on non-exempt lines (verified via deliberate-break test). Small perf + big-O improvement for the common case.

## Rule derived

**For class-fix instance PRs (applying a pre-existing `_shared/<contract>.md`), the shape is:** STOP-block prose naming the specific improvisation phrases verbatim + regex entries in the existing linter + Gotcha bullet update naming shipped instances. No new shared file, no new linter, no fixture — the class-fix template already owns those surfaces. Bundle siblings that edit the same consumer file into one PR. Follow-up issues for refinements (e.g. per-phrase-span exempt) are healthier than over-engineering in v1.

**Sub-rule:** exempt-pattern design for content-level linters mirrors existing intent filters (cf. `PROSE_PATTERNS` ↔ `FORBIDDEN_EXEMPT_PATTERNS`). Line-level intent detection (italic-quote + negation cues) beats section-level heuristics when the sections-that-would-need-exempting aren't scanned anyway. Validate `_collect_targets`' glob coverage before adding section-level exemptions.

**Sub-rule:** when simplify-pass flags an over-broad exemption cue in a linter (e.g. "W17 dogfood" in `FORBIDDEN_EXEMPT_PATTERNS`), treat it as security-adjacent — the exemption is the mechanism that *allows* phrases through, so over-breadth is effectively a false-negative bug, not a style choice. Tighten aggressively.

**Sub-rule:** bundled-PR commit shape = `main-work` + `simplify-pass` + `review-follow-up-doc`. Three commits keep history atomic and reviewable; avoids the "one giant commit with everything" trap when review-phase changes are genuinely separable.

Template applies to the next BC-5868–BC-5873 / BC-5900 / BC-5901 as they land — each extends FORBIDDEN_PHRASE_PATTERNS and/or adds a STOP block as their specific remediation, with the shared contract infrastructure reused.
