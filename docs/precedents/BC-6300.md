## Task 2 — Plan-file co-location with worktree (orphan-prevention)

**Date:** 2026-04-28
**Category:** pattern-choice
**Confidence:** 7/10
**Tags:** pattern-choice, plan-file-location, worktree-discipline, orphan-prevention, execution-hygiene

### Decision

Write the plan file to the worktree (not the main repo's `docs/plans/`) and commit it as part of the PR — never leave the plan as an untracked artifact in main. When the worktree doesn't exist yet at plan-write time (Step 6 of session-start runs before Step 7 worktree creation), write to the main repo first for approval, then **copy** the plan into the worktree at worktree-creation time and **delete** the main-repo copy in the same operation.

### Inputs

- BC-6298 plan file orphaned in main repo (`docs/plans/BC-6298-plan.md`) — never made it to PR #228 because I wrote it before creating the worktree and never moved it
- BC-6306 plan file successfully committed to PR #227 (commit `92a0e12: BC-6306: design doc + plan`) — the pattern this trace ratifies
- BC-6300 worktree-creation Bash chained the cp/rm explicitly to fix BC-6298's slip + clean up the orphan in one operation

### Alternatives Considered

1. **Write to main, copy to worktree at creation, delete main copy** *(chosen)* — addresses the timing constraint (plan must exist for user approval before worktree is created) without leaving an orphan. Single Bash invocation handles cp + rm. Plan rides the PR via the worktree's working tree.
2. **Write directly to worktree only** — rejected because the worktree doesn't exist yet at Step 6 (plan-write phase). Reordering Step 7 to precede Step 6 would require restructuring the inner-loop spec.
3. **Leave the plan in main as untracked + just commit it from main during PR cleanup** — rejected because main-repo writes during a feature session pollute the main working tree; future session-start runs would warn about an "untracked" plan from a shipped issue. Plan-file home is the PR branch, not main.
4. **Skip the plan file entirely** — rejected; plan files are durable artifacts (see `docs/plans/BC-5906-plan.md` reuse pattern for round-3 dogfood). They belong in the repo's history.

### Outcome

- **Files changed:** `docs/plans/BC-6300-plan.md` written to main, copied to worktree, removed from main (one Bash chain); BC-6298 orphan also removed in the same chain.
- **Tests:** N/A
- **Approved by:** auto-applied during BC-6300 worktree-creation step

### Precedent Referenced

BC-6306 (the pattern this ratifies — plan + design committed to PR); BC-6298 (the slip this corrects — plan never rode PR #228).
