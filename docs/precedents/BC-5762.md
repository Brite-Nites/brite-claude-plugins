# BC-5762: BC-5761's 4-5 iteration precedent confirmed on a second markdown-spec PR; Bash-variable-without-producer is a distinct bug class from printf-with-prose-placeholder

**Date:** 2026-04-20
**Category:** pattern-choice
**Confidence:** 8/10

## Decision

Two independent observations from the BC-5762 review loop, each load-bearing for future cadence/markdown-spec work:

1. **BC-5761's "fix-review loops converge in 4-5 iterations" precedent is now observed on a second markdown-spec PR.** BC-5762's iter 1 found 5 P1s + 10 P2/P3s; iter 2 found 5 NEW P1s from iter-1 drift + 2 P2s. Same shape as BC-5761: iter N+1 surfaces P1s *introduced by iter N's fixes*, not residuals the reviewers missed. Two observations is a pattern. Budget 3 hours of parallel agent time per destructive-path markdown skill PR.

2. **"Bash variable referenced but never assigned" is a distinct bug class from BC-5760's "printf-with-prose-placeholder".** BC-5760 flagged `printf "<placeholder>"` as a class. BC-5762 iter 2 surfaced three instances of a related-but-different trap: `$DRAFT_PATH`, `$NARRATIVE_MD`, `$PDF_PATH` each referenced inside Bash blocks with no producer shown in the spec. The distinction matters because the bug is not about printf or angle brackets — it's about any shell variable in an LLM-executable spec without an explicit assignment site. Codified as a new gotcha in plugins/cadence/CLAUDE.md § Gotchas: "Every `$FOO` in a Bash block must have a visible producer in the same section or explicit prose telling the main thread to mint/export the variable before the block runs."

## Alternatives Considered

1. **Skip iter 2, ship after iter 1** (accept iter-1 residuals). Rejected — iter 2 found 5 NEW P1s, 3 of which were introduced by iter-1 fixes (audit.json folder drift, bash-var references, § 4.5 re-derivation). Shipping without iter 2 would have left a broken Phase 4 voice-check + a broken Phase 5 `$PDF_PATH` confirmation. Strictly worse than one more iteration.

2. **Run iter 3 before shipping** (full BC-5761 precedent convergence). Considered but declined. iter 2's P2s were all policy/polish (path-resolution deduplication, rehydration field completeness, `<if>/<else>` syntax consistency). iter 3 typically finds ≤ 2 new P1s on smaller specs and the runtime dogfood (BC-5763) will surface any remaining correctness bugs faster than another review loop. User called it on iter 2; decision matched the precedent's "cap at 5, ship with residuals documented" framing.

3. **Single-commit vs iter-per-commit** (chosen). Chose single commit for this PR because the iter 1 + iter 2 fixes all land on the same un-committed initial diff (no prior push). BC-5761 used 7 commits because each iter pushed. No perceptible difference in git history legibility; single-commit is less bureaucratic when no reviewer is observing intermediate states.

**Reusable beyond this case:**

- **Iteration budget for cadence follow-ups.** BC-5763 E2E dogfood is a smaller change (harness + smoke tests) and should converge in ≤ 2 iterations. BC-5821 prior-narrative parser is comparable in scope to BC-5760 and should budget for 4-5.

- **"Bash variable needs a producer" class of spec bug.** Add to `memory/gotcha_write_tool_worktree_path.md`-adjacent rules: every Bash block in a skill/command/agent markdown must either (a) assign `$FOO` inline before first use, (b) name the state field that the main thread template-substitutes before invoking Bash, or (c) include a prose bullet telling the main thread to mint + export the variable. Missing producer = class B broken spec, same severity as missing printf placeholder.

- **Cross-cycle folder drift gotcha.** When a multi-phase plugin has artifacts tied to different cycle identities (Phase 1 audits the *previous* cycle, Phases 2-5 plan the *current* cycle), put all artifacts under the CURRENT cycle's week folder. The internal `cycle.id` field inside each artifact identifies the audited/planned cycle. Avoids the "which folder does audit.json live in?" confusion that iter 2 surfaced. Captured in plugins/cadence/CLAUDE.md § Gotchas (BC-5762 amendment).

- **Tool-availability degradation for optional user-level MCPs.** The `mcp__computer-use__write_clipboard` → `pbcopy` fallback pattern (new for this repo) should be considered for codification in `docs/guides/skill-tool-integration-pattern.md` if other plugins surface the same need. Not promoted yet — one data point.
