# BC-5824: Fetch handbook canon during brainstorm/design time, not during execution

**Date:** 2026-04-20
**Category:** pattern-choice
**Confidence:** 7/10

## Decision

When any brainstorm or design conversation touches handbook-governed scope (verticals, ICPs, personas, entity canon, offer taxonomy), fetch and read the handbook source file BEFORE solidifying a design decision — not during execution. Memory and user-supplied context are not authoritative; the handbook is. Scope assumptions made without the source will need re-drafting mid-implementation and cost a design-doc revision plus a task-by-task correction sweep.

## Context

BC-5824 was a net-new skill creation — `situation-mining` — that included a design doc with four decisions. Decision D4 set Brite-adaptation coverage of the inline worldview matrix + adjacent-offering mappings to "all 23 verticals." During the brainstorm AskUserQuestion flow, Claude presented an option labeled "All 23 verticals (Active + Exploring + Future + Supply-deferred)" and framed it as a *departure* from BC-5823's "Supply-deferred" precedent. The user selected that option.

Task 1 of the execution plan then fetched `Brite-Nites/handbook@main:marketing/go-to-market/verticals/README.md` for the first time and discovered:

- The canonical 23-vertical taxonomy is **6 Active + 8 Exploring + 9 Future**.
- All 23 are Nites + Labs only — **Supply verticals (professional installers, property management) are explicitly excluded from the taxonomy** per the handbook's own Excluded-from-taxonomy note.

The framing that "23 includes Supply" was wrong. BC-5823's Supply-deferred precedent was never being reversed — it was being faithfully applied. The design doc D4 section had to be rewritten, the plan Task 5 examples had to lose two Supply rows (installer hiring, property mgmt RFP), and the plan Task 11 precedent-clarification step had to be removed (no BC-5823 clarification was needed).

## What the fix looks like

- **At brainstorm time**, when a decision option references handbook-governed scope, the skill should fetch the handbook file via `gh api` (per `memory/reference_handbook_access.md` — Context7 does not resolve the private handbook) and quote the relevant section into the conversation before presenting options via AskUserQuestion.
- **In the design doc**, record the handbook file path + fetched snippet as Source, so the reasoning trail is reproducible.
- **In the plan**, Task 1 (or an earlier Task 0) is the handbook fetch, not "fetch + draft" — the fetch precedes any commitment to content scope.

## Precedent referenced

- **BC-5823** — "Handbook canon wins over issue-body scope for vertical/ICP/persona decisions." This precedent established what to consult; BC-5824 refines *when* to consult it. Together: handbook canon wins, and you must read it at design time.

## Confidence

7/10. The process rule is clear but the cost of not following it was small in this case (one design-doc section rewrite + six lines of plan edits). If the mistake had surfaced after the 46 content rows had been drafted to include Supply, the cost would have been much higher — so the rule's value scales with the draft depth at which the error is caught.
