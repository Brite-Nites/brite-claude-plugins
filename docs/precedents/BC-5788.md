# BC-5788: Keep upstream skill names when adopting external plugins via git subtree

**Date:** 2026-04-19
**Category:** pattern-choice
**Confidence:** 8/10

## Decision

When adopting an external open-source plugin via `git subtree`, preserve upstream directory and skill names rather than renaming them to a Brite-branded prefix (e.g., `sf-*` stays `sf-*`, not renamed to `brite-*`). Brite ownership is signaled via the plugin namespace (`plugins/revops/`), an in-file attribution header, and customized SKILL.md content — not via directory renaming.

## Context

The RevOps plugin master plan §3.6 (docs/plans/revops-plugin-master-plan.md, 2026-04-19) locked a convention to rename all adopted Jaganpro skills from `sf-*` to `brite-*` during Phase 3 customization. During plan review, the user pushed back on the rationale — the plugin namespace already carries the Brite signal, and renaming creates long-term friction with any future `git subtree pull` from upstream. The reversal was ratified in ADR-007 §3.6.

## Alternatives Considered

1. **Rename to `brite-*`** (original master plan §3.6) — Rejected: plugin namespace already signals ownership, attribution header carries provenance, every rename is a merge conflict during `subtree pull`.
2. **Keep upstream names** (chosen) — Upstream-sync path stays mechanical. Brite ownership carried by plugin namespace + attribution header + customized content.
3. **Per-skill decision with justification** — Deferred into §3.7: default is "no rename" but a skill-specific reason can override per issue.

## Outcome

ADR-007 §3.6 documents the convention override. Applies to all Phase 3 skill customization issues (BC-5793-5804) — each ships as a content-customization (attribution header + SKILL.md edits + references/) without directory rename. The master plan §3.6 remains as historical record with a pointer to the ADR superseding it.

**Precedent Referenced:** None — new pattern. Applies to future plugin adoptions (any external open-source Claude Code plugin imported via `git subtree`).
