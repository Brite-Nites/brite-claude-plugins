## task-1 — 2nd surface of BC-6996 task-1: operationalize gh api URL resolution inside-the-loop

**Decision:** BC-6996 task-1's lesson — "the verification protocol matters more than the reviewer's intelligence; review agents see URL strings, not resources; cross-repo URL drift survives every internal review iteration that doesn't touch the network" — has been moved from author-time discipline to agent-prompt enforcement. The cdr-compliance-reviewer now extracts GitHub URLs from added/modified diff lines, deduplicates, probes each unique `(owner, repo)` for accessibility, then runs `gh api repos/${owner}/${repo}/contents/${path} -f ref=${ref} --silent` per unique URL. 404 at a public repo → P1 confidence 10/10. 404 at a private/inaccessible repo (where the per-repo probe also returned 404) demotes to an informational note rather than P1 — GitHub deliberately returns 404 not 401 for private repos to callers without read scope, so a child-path 404 is ambiguous between "file missing" and "repo private," and `Brite-Nites/handbook` is the canonical handbook target. The protocol is now load-bearing for the cross-repo URL drift class.

This is the 2nd surface of BC-6996 task-1 (1st surface: BC-6996's own broken CDR-014 URL caught only by the independent post-PR reviewer). The 2nd surface validates that the precedent's chosen-alternative (encode the discipline into cdr-compliance-reviewer) is feasible, fits the existing review-agent surface area, and does not introduce a new agent slot. The PR is intentionally pure-prompt + version bumps — zero runtime code, zero schema change, zero breaking API — so the entire fix surfaces immediately to the next /workflows:review run.

## task-2 — META-PRECEDENT: cross-document references need ground-truth verification at authorship; encode protocol into review-agent prompt, not into author memory

**Decision:** **PROMOTING the meta-precedent BC-6996 task-1 anticipated.** Three distinct surfaces, each on a different artifact class, each surviving multiple review iterations, share the same root-cause shape: a reviewer that compares strings cannot detect a reference that drifted from its target:

- **Cross-repo URL drift** (BC-6996 task-1) — `CDR-014-phase-pattern.md` slug 404s; actual file: `CDR-014-milestone-standards.md`. Survived 3 thorough `/workflows:review` iterations + 4-agent dispatch each. Caught only by `gh api` resolution.
- **Internal line-cite drift** (BC-6955-rework task-1) — 7 line-citation errors (`:281`→`:292`, Q46 range `:986-1048`→`:997-1059`, etc.) shipped through PR #263 + `/workflows:review` + `/workflows:ship`. Caught only by fresh-authorship + per-cite source-file verify against the upstream design rationale.
- **Integration-doc contract drift** (BC-6907 task-2) — docs still describe a DELETED artifact's I/O. Runtime triage rates it "trivial" because the executable contract is preserved; only the architecture-reviewer's structural lens surfaces it. Caught only by structure-aware diff reading, not by string-comparison.

The unifying pattern: **any cross-document reference — URL slug, line number, anchor link, file path, API contract description — needs a ground-truth fetch at authorship.** String-comparison review provably fails for this class because the failure mode is "the string is consistent with itself but inconsistent with the target." The reviewer would need to fetch the target to detect the mismatch, which a string-aware-only agent cannot do.

The fix-shape is also unified: **encode the verification protocol into the review-agent prompt that owns the artifact class, not into author memory.** Author memory fails on the 100th edit; the agent prompt fires on every edit. BC-6996 task-1 chose this fix-shape for cross-repo URLs (operationalized by BC-7446 task-1). The same fix-shape extends to the other two surfaces:

- **For internal line-cites** — a future review-agent extension reads cited file paths + line numbers from the diff and verifies content matches expected Q-number / heading.
- **For integration-doc contracts** — the architecture-reviewer's structural-lens check should be made non-optional whenever a deletion-style refactor touches an artifact with integration-doc cross-references.

**Generalization principle for future agent design:** When a review agent specializes in an artifact class (CDRs, design rationale, integration docs), and the artifact class contains cross-document references that point at other artifacts, the agent's prompt MUST include a ground-truth-fetch step for each reference — not a string-validity step. The cost is bounded (N fetches per review where N = unique refs in the diff). The benefit compounds — every author for the lifetime of the agent is freed from remembering to verify.

**Confidence:** 9/10 (3 documented surfaces across distinct artifact classes; fix-shape is consistent and proven viable in BC-7446 task-1; generalization is concrete and testable — not aspirational)
