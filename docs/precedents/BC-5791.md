## Rule derived

**For second-of-N template-inheriting commands, the thorough-mode review + per-finding Opus/Sonnet validation shape is ratified.** This specific pipeline catches three classes of issue that would escape a lighter review:

1. **Template-tension BC-5795 violations** — pragmatic shortcuts inherited from the first-of-N can conflict with the Rules contract when the second sibling adds stricter discipline. The cdr-compliance agent caught the Phase 5 "missing or zero" conflation that neither BC-5790 nor my own pre-review pass surfaced.
2. **New-content correctness bugs in parts the template doesn't cover** — the CustomField `__c` stripping bug and Flow versioned-rows bug are both in Phase 6 (Tooling API SOQL) which doesn't exist in BC-5790. Opus verifier confirmed SF API semantics from trained knowledge without live-org access.
3. **Noise that validators dismiss with principled reasoning** — 5/8 non-P1 findings were DISMISSED (SOQL injection false-alarm, parse-once non-issue, CustomField-consolidate-loses-affinity, numberComponentsTotal-is-stable, git-status-disclosure-is-local). Without the validation step, over-fixing would have added noise and made the command harder to maintain.

**Sub-rule (plan discipline):** declare sibling-specific departures from template in the plan file's §Departures section before writing any code. BC-5791 did this for 6 overrides; no mid-execution drift. Pattern generalizes: any template-inheriting sibling issue should plan its departures upfront so review can verify plan<>implementation alignment rather than deriving the template contract from the diff.

## How to apply

- **When:** shipping any template-inheriting sibling command (BC-5792 post-deploy-runbook next; any future Phase 3 sibling that inherits BC-5798's six-sibling skill template).
- **Review shape:** thorough mode, 4 agents (code + security + performance + cdr-compliance; add typescript/python/data via auto-detect if stack markers present), per-finding Opus for P1 + Sonnet for P2/P3. This is the ratified sibling-two shape.
- **Simplify discipline:** template-inherited duplications stay; sibling-introduced duplications can be trimmed. Check BC-5790's corresponding file before auto-fixing preamble patterns.
- **Plan discipline:** include a §Departures section listing every override from the template; review verifies the diff matches.
- **CLI-shape verification:** Opus validators trust trained SF / cloud-SDK knowledge — no live-org round-trip needed for shape questions like `DeveloperName` suffix rules or field-presence-in-envelope. Dispatch without hesitation.
- **Use `origin/main` as BASE:** when other parallel workstreams may have advanced the remote, local `main` lags. Compute BASE = `origin/main` explicitly at session start, not `main`.
