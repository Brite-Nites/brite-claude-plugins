# BC-5797: Sibling-four proves template durable across five siblings; factual-anchor recipe gains two checks (Linear citation, verify-matrix regex)

**Date:** 2026-04-20
**Category:** pattern-choice
**Confidence:** 7/10

## Decision

After five consecutive Phase 3 siblings applying the same template (BC-5793 → BC-5794 → BC-5795 → BC-5796 → BC-5797), the template is no longer "proving" itself — it IS the Phase 3 shape. Ship every remaining Phase 3 sibling mechanically with zero Plan-gate re-derivation, but treat the pre-merge `/workflows:review` as a mandatory gate per BC-5796, and extend the factual-anchor recipe with two new checks: (4) live Linear verification for any issue-ID citation in rule text, and (5) verify-matrix regex pre-check (every `grep` pattern in the issue-body verify matrix must match the drafted SKILL.md before Execute is considered complete).

## Context

BC-5797 customized `plugins/revops/skills/sf-metadata/SKILL.md` with 21 Brite metadata-authoring rules — the 4th Phase 3 sibling in the RevOps plugin milestone and the 5th skill overall following this template (counting BC-5795 v2 as sibling-two).

All inherited departures from the issue body (no rename, no `git mv`, verify T1/T3-T7 stay on upstream path) applied verbatim per BC-5794's "no re-litigation" rule. Template variant B placement (Brite sections BEFORE `## When This Skill Owns the Task`) chosen without re-litigation — now majority 3-of-4 siblings.

Pre-merge `/workflows:review` (thorough, 4 agents: code, security, performance, cdr-compliance) surfaced 0 P1, 3 P2, 7 P3. The top-confidence P2 [9/10] was exactly the BC-5795 class: an internal rule-count contradiction between `§Brite Context` ("18 in scope") and See-also ("distilled into Rules 5-21" — which is 17 rules). The simplify-quality pass caught it first at P2; the code-reviewer agent independently corroborated at P2 [9/10]; the orchestrator applied a 1-line fix pre-commit. Triple-signal → direct-apply, no Opus validation needed.

Independent verification added value in two places:
1. **BC-4734 citation verified live.** Rule 15 cited "Verified empirically against `Contact.Lead_Status__c` (BC-4734, 2026-04-07)". cdr-compliance agent (no Bash) flagged the citation as unverifiable from its context. A 30-second `get_issue(BC-4734)` confirmed status Done, completedAt 2026-04-07, and — more importantly — `brite-salesforce/CLAUDE.md` line 132 echoes the same citation verbatim. Finding DISMISSED by direct verification; citation sound.
2. **T5 regex mismatch caught during Execute.** Rule 11 initially said "Restricted-picklist" (hyphenated, capital R). Issue-body verify matrix expected `grep -E "restricted picklist|..."` (lowercase, space). T5 failed on first run. One-word edit fixed it. This wasn't caught by any review agent — it was caught by running the verify matrix before claiming Execute complete.

## Alternatives Considered

1. **Skip `/workflows:review` entirely — template is proven.** Rejected. BC-5796's prescription was pre-merge review IS the compound-engineering instrument that makes BC-5795 revert+reship rare. Skipping would test whether 5-sibling streak is enough to drop the discipline. That test's value is low — the downside (post-merge P1 factual error → revert+reship) is expensive; the upside (~5 min saved) is cheap. Honor the instrument.

2. **Accept the diff-triage TRIVIAL verdict (BC-5823/5824 pattern).** Considered. The Haiku triage agent correctly verdicted TRIVIAL by shape (markdown-only, no code) — matches BC-5823/BC-5824 precedent. But markdown-only skill customizations with numbered rules + cross-references + factual citations have content-correctness risk that triage cannot see. Per `feedback_honor_user_gate_selection.md`, the TRIVIAL/thorough choice is a user-gate: the orchestrator surfaced both options with tradeoffs (BC-5823 pattern: ship as TRIVIAL; BC-5796 pattern: escalate to thorough). User chose escalate. Value demonstrated: 7 pre-merge fixes applied in markdown content that TRIVIAL would have shipped unreviewed.

3. **Run `/workflows:review` thorough (chosen).** Applied. 7 pre-merge fixes landed in 3 edits plus one regex-case tweak. Cost: ~3 minutes of reviewer turns. Benefit: no BC-5795-class factual error reached commit; the same factual-error class that triggered BC-5795's revert+reship (P1 in post-merge review → revert + new PR) was caught at the P2-equivalent severity pre-commit.

## Outcome

Delivered `plugins/revops/skills/sf-metadata/SKILL.md` (+63/-3, 21 rules) + `docs/plans/BC-5797-plan.md` (new, +196) as a single commit → PR #155. All 10 tests in the verify matrix either PASS (T1-T7, T10) or are deferred post-merge per BC-5793 (T8, T9). `./scripts/validate.sh` clean (0 errors, 17 pre-existing warnings — same baseline as BC-5796). Review verdict after 4 agents + pre-merge fixes: **ready to ship, 0 known issues**.

**Reusable beyond this case.** The factual-anchor recipe is now five checks deep:

1. **Line-range citation** — every rule cites a specific source line in `brite-salesforce/CLAUDE.md` (BC-5793-5796).
2. **Bullet-count verification** — `gh api | sed -n 'A,Bp' | grep -c "^- \*\*"` to confirm the actual bullet count before making "~N gotchas" claims (BC-5796 introduction).
3. **Canonical path verification** — every file path named in rule text exists in `brite-salesforce` main (BC-5793-5796).
4. **Live Linear verification for issue-ID citations** (new). Any rule that cites a `BC-NNNN` issue should be checked via `get_issue` during Explore: verify status, date, and (critically) whether the handbook itself cites that issue. If the handbook doesn't cite it, the rule's historical claim becomes dangling — drop the parenthetical.
5. **Verify-matrix regex pre-check** (new). Every grep pattern in the issue-body verify matrix must be run against the drafted SKILL.md before Execute completes. Regex case-sensitivity + word boundaries are a separate correctness dimension from rule content. Not catching this costs a post-Execute "T5 failed" loop that BC-5796 and BC-5797 both hit.

**Secondary observation: simplify pass finds factual bugs in markdown skills, not just style.** The simplify-quality agent caught the rule-count off-by-N + stale verify-matrix rule numbers (T3 said Rule 4 / should be 5; T5 said Rule 10 / should be 11; T6 said Rules 17/18 / should be 17-19; T7 said Rules 7/8 / should be 8/9) before the review agents even dispatched. Simplify-quality agent IS a high-ROI content reviewer on numbered-rule markdown, not just a stylistic trimmer. Worth adding to the `/workflows:review` narrative: on markdown skills with numbered rules + cross-references, simplify-quality is a front-line factual-error catcher, not just a second-order style pass.

**Tertiary observation: user gate at TRIVIAL/thorough pivot is a productivity multiplier.** BC-5823/BC-5824 established that TRIVIAL is correct for markdown-only skill ports. BC-5796/BC-5797 established that TRIVIAL MIGHT miss content-correctness bugs on numbered-rule skills with cross-references. The resolution: surface the choice with both tradeoffs, honor the user's selection per `feedback_honor_user_gate_selection.md`, don't self-override. BC-5797 picked thorough and got 7 fixes; BC-5823 picked TRIVIAL and shipped clean. Both correct.

**Quaternary observation: security hook behavior is now clearly broken on `git push`.** BC-5824 broke the 6-consecutive-session streak where the security hook blocked `git push`. BC-5797 is the 7th consecutive session where the push was unblocked. This is enough evidence to update `gotcha_security_hook_blocks_infra.md` — the hook likely changed behavior between 2026-04-14 and 2026-04-19. Flag for memory update (not part of this precedent, but a cross-cutting observation).

**Strengthens** BC-5796 (template durability claim → now 5 siblings strong). **Extends** BC-5793/5794/5795/5796 factual-anchor discipline with two new checks. **Does not change** BC-5794's "no re-derivation at Plan gate on sibling siblings" rule — reinforces it.
