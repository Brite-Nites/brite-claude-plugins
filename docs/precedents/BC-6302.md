## Task 1 — Plain-language gist before the formal plan, especially when issue body is dense

**Date:** 2026-04-29
**Category:** pattern-choice
**Confidence:** 7/10
**Tags:** plan-gate, plain-language-gist, jargon-bridge, plan-write-pause, communication-discipline

### Decision

Before writing a multi-page plan to disk, offer a 2-paragraph plain-language gist — `(a)` what's wrong today, `(b)` what the fix does in human terms — and wait for the user to confirm the gist matches their understanding. Do this proactively when the issue body is dense (jargon, code snippets, multi-numbered scopes, internal acronyms). Only proceed to plan-write after the gist is acknowledged.

This extends `feedback_jargon.md` (plain-language over engineering terminology) with a workflow-level rule: the *form* of the first artifact matters as much as its *vocabulary*. A long plan file is the wrong first artifact for first-pass alignment; a conversational gist is.

### Inputs

- BC-6302 issue body has dense scope language: "Phase 5 step 4 (User gate 5) — add a conditional ⚠️ N campaigns already exist with prefix `{base}` …", three numbered edit points, references to `list_campaigns`, `create_campaign`, F20 finding evidence with API call/response pairs, multiple cross-issue precedents
- Mid-session, the user interrupted plan-write with: *"can you tell me plainly what this linear issue entails?"* The plan-write tool use was rejected.
- After plain-language gist, user asked a clarifying check: *"so this will check with the user whether or not it should be a duplicate before just going ahead and adding the duplicate?"* — confirming they were forming the right mental model
- Following confirmation example render, user said: *"okay we can continue. this makes sense to me"* and plan-write resumed and was accepted on the second attempt
- The interruption did not reflect a problem with the plan content (which was accepted unchanged on retry); it reflected a missing alignment-check artifact between issue-pick and plan-write
- Existing `feedback_jargon.md` memory says "plain-language explanations over engineering terminology in design discussions" — but the trigger had previously been on user request, not proactive

### Alternatives Considered

1. **Always offer a 2-paragraph gist between issue-pick and plan-write when issue body is dense** *(chosen)* — costs ~30 seconds, but eliminates the failure mode of writing a 100-line plan the user can't engage with. Aligns with the existing jargon-accessibility feedback. Density triggers: jargon, multi-step scope, code blocks, nested conditionals, internal-only acronyms.
2. **Wait for user to ask for a gist (the prior default)** — rejected. The session's signal is that asking-for-gist costs the user a context interruption and a tool rejection; the cost of a proactive gist is far lower than the cost of a wasted plan-write attempt.
3. **Always do plan-first-then-gist (current behavior with retry)** — rejected. The plan file is auditable and stable, but the conversational gist is cognitively load-bearing for alignment. Inverting these means alignment lands first; the plan is ratification, not introduction.
