## Task 2 — Superset interpretation when issue spec quotes one cluster shape but cluster spans multiple

| Field | Value |
|---|---|
| **Decision** | When an issue spec quotes a precedent cluster's rule text scoped to one shape but the cluster's actual surfaces span multiple distinct shapes, the baked-in rule should be a superset covering all shapes the cluster proved load-bearing — not the narrowest shape the issue spec quoted. Narrowing to the quoted shape would re-orphan the surfaces the issue is supposed to promote. |
| **Category** | pattern-choice |
| **Confidence** | 7/10 |
| **Precedent Referenced** | None (new class for the codebase precedent record) |

**Inputs**
- BC-7065 issue body quoted the BC-7051 shape only ("script + canonical reference document") — narrowest of the 3 cluster shapes
- Cluster surfaces span: (1) `docs/{decisions,designs,research,precedents}/` paths from BC-5786/5820; (2) routing artifacts `plugins/<plugin>/skills/<skill>/SKILL.md` + commands/agents from BC-6436; (3) script + canonical ref doc combination from BC-7051

**Alternatives Considered**
1. **Chosen** — Bake in the superset rule covering all 3 cluster shapes. Bullet 1 covers (1); bullet 2 covers (2) with `**/skills/**/SKILL.md` glob hardening; bullet 3 covers (3) with explicit canonical-doc list (`**/UPSTREAM.md`, `**/CLAUDE.md`, `**/CONTRIBUTING.md`, `**/ARCHITECTURE.md`, plugin `README.md`).
2. Rejected — Bake in only the issue-quoted BC-7051 shape. Would leave BC-5786/5820/6436 surfaces semantically orphaned from the very PR that promotes them. The 4 precedent trailers would point to a rule that doesn't fully encode the cluster's lessons.
3. Rejected — Bake in only the cluster's documented path-prefix exact forms (no `**` globs). Misses future drift (e.g., a `SKILL.md` relocated to a sibling path). Security-reviewer's filtered P3 specifically flagged this; the `**` globs incorporate the hardening.

**Outcome**
- Rule covers all 3 cluster shapes + uses `**` globs for routing-artifact future-proofing.
- Originating issue's acceptance criteria all met (the quoted rule text is not a literal-text requirement — the acceptance criterion is "load-bearing-doc-artifact rule as a default heuristic").
- Self-consistency verified: this PR's diff (which contains 4 `docs/precedents/` files + 1 routing artifact, NOT a script+ref-doc combination) would have been MISSED under the narrow interpretation; the superset catches it on bullets 1 and 2.

**Generalization**: When an issue spec quotes prescriptive text for a precedent-cluster promotion, treat the quoted text as **one valid expression** of the rule, not the only valid expression. The rule's purpose is to capture the cluster's lessons; if the cluster spans more shapes than the issue's quote covers, expand to cover them. Cross-check by counting the cluster's distinct decision shapes vs the quote's coverage; if shapes > quote-coverage, expand. Document the expansion choice in the PR body so future maintainers see the intentional widening.

## Task 3 — Self-consistency meta-test: dispatch the new rule against the PR that adds it, before ship

| Field | Value |
|---|---|
| **Decision** | When shipping a rule change to a classification agent, dispatch the agent on the PR's own diff at both commit-time AND after any review-fix amend, before the ship-gate. The meta-test catches malformed rule encodings, off-by-one path patterns, and over-narrow/over-broad bullets that abstract reading misses. |
| **Category** | architecture |
| **Confidence** | 8/10 |
| **Precedent Referenced** | None (new class for the codebase precedent record); adjacent to BC-6436 trace 2 (preventative dispatch-time priming as upstream form of the same concern) |

**Inputs**
- BC-7065 PR adds a new auto-NON-TRIVIAL classification rule to the diff-triage agent
- Two diff-triage agent dispatches in this session (initial post-commit + post-rewrite after amend); both classified the PR's diff as NON-TRIVIAL citing specific new bullets
- Counter-factual: a malformed glob (e.g., `**/agents/*.json` instead of `*.md`) would have produced a different classification or cited the wrong bullet, surfacing the encoding error before push

**Alternatives Considered**
1. **Chosen** — Dispatch the agent on its own PR's diff at both commit-time AND after any review-fix amend. Captures the rule in actual use, not abstract reading.
2. Rejected — Trust the abstract reading of the rule against the diff. Misses encoding bugs (path glob typos, missing escaping, semantic mis-bracketing).
3. Rejected — Defer self-consistency check to post-merge production traffic. Late signal; reviewers and downstream tests don't catch agent-prompt encoding bugs in time to avoid churn PRs.

**Outcome**
- Two dispatches in this session: initial post-commit + post-rewrite amend. Both passed (NON-TRIVIAL with correct bullet citation).
- Cost: ~6-8s wall time per dispatch + Haiku tokens (sub-cent); cheap insurance.
- Pattern is generalizable to any prompt-shipping PR (review-agent prompt changes, simplify-agent prompt changes, dispatch prompts in `commands/*.md`).

**Generalization**: Prompt-encoding bugs are a distinct failure class from logic bugs or factual bugs. Reading the prompt doesn't exercise its parsing path; only dispatching does. For any PR that changes a classification or routing prompt, schedule a self-dispatch as a ship-gate before push. The dispatch should be against a known-shape diff (ideally the PR's own diff, which has known semantic ground truth — "should classify as X because the PR is itself a Y-shape change"). Promote to ≥4-surface threshold pattern if this meta-test catches a real encoding bug in a future PR.
