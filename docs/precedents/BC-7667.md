## BC-7667 task-1 — Dual-reading disambiguation when re-validating ambiguous prior-round hypotheses

**Confidence:** 8/10
**Category:** Process / dogfood-walk methodology
**Promotion candidate:** Yes (sibling of BC-6780 task-1 vocabulary-capture; BC-6784 task-1 live-vs-archaeological)

### Context

BC-7667 round-6 R-6 carried this hypothesis from round-5: *"forced duplicate-email in chunk → all-or-nothing 422 (Sx-8 atomic rejection)."*

The phrase "in chunk" has two plausible readings:
- **(a)** Within-chunk duplicate: two leads with the same email in a single `POST /api/leads/multiple` body.
- **(b)** Re-POST of an existing-in-workspace lead: one lead in the body whose email already exists in EB.

Round-5's actual test was (b) (verified by reading `docs/dogfood/bc-6554-round-5/round-5-transcript.md:225–228` — the transcript described "already-existing lead from R-5★ mass-create" returning HTTP 422). The round-5 hypothesis prose, however, sounded more like (a).

### Decision

**Run BOTH readings at runtime to disambiguate.** Don't just pick one and ratify the prior round's verdict — that would inherit the prior round's interpretation without testing the alternative.

### Outcome (round-6 R-6)

- **(a) within-chunk dup:** HTTP 201 success, server **silently dedupes** (only first occurrence created). **NEW behavior**, undocumented in EB gotchas. → Filed as **BC-11071** (loop-close follow-up).
- **(b) re-POST existing:** HTTP 422 atomic rejection. Confirmed round-5's actual test verdict. → Sx-8 behavior intact.
- **Side-discovery:** `launch-campaign.md:454` prose claims re-POST "upserts in place" citing BC-6785 R-28. Both claims wrong — R-28 verified upsert-VARIANT endpoints don't exist, NOT that `/api/leads/multiple` upserts. → Filed as **BC-11072**.

Running both readings produced 3 outputs from 1 hypothesis: ratification of (b), discovery of (a), and discovery of the spec contradiction. Picking only (a) would have inverted the verdict. Picking only (b) would have missed the silent-dedup behavior + the spec contradiction.

### When to apply

- Re-validating a hypothesis from a prior dogfood round whose wording allows multiple readings.
- Wording cues: "in X" (where X has scope ambiguity), "with Y present" (where Y could be in-batch or external), "duplicate Z" (within-chunk vs vs existing).
- Cost is low: usually one extra API call. Signal yield is high: catches both behavior change and stale doc claims.
