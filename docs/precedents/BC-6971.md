**Confidence:** 8/10

The 16 ACs cover all load-bearing strings (agent names, flags, mode values, atomic-write phrasings, final-review option set). - Compare with BC-6977 task-2 (301 LOC spec + shell + cite chains): 4-iter floor. BC-6959 task-2 (1500+ LOC): 4-iter floor. BC-6973 task-4 (pre-existing drift at iter-3): 5-iter extension. **Alternatives Considered:**

3. Treat 2-iter as a one-off anomaly — rejected; the prediction is structural (AC grep matrix → no drift), not session-specific. Need to surface again before promoting to load-bearing.

**Outcome:**

- Tests: validate.sh 0 errors at both iter-1 fix commit and iter-2 verification. All 16 ACs pass at both checkpoints.

## task-4 — `gh pr merge --delete-branch` worktree contention (gotcha + workaround)

<a id="BC-6971-task-4"></a>

**Decision:** `gh pr merge <N> --squash --delete-branch` fails its post-merge local-cleanup step with `fatal: 'main' is already used by worktree at <primary>` when invoked from inside `.claude/worktrees/<name>/`. The PR merges fine on GitHub; only the local-branch-delete fails. Workaround: confirm merge via `gh pr view <N> --json state,mergedAt`, then delete the remote branch via `gh api -X DELETE repos/<org>/<repo>/git/refs/heads/<branch>`. Local branch stays in the worktree and auto-cleans when the worktree is removed.

**Category:** bug-resolution

**Confidence:** 9/10

**Inputs:**
- `gh pr merge 309 --squash --delete-branch` invoked from `.claude/worktrees/bc-6971-office-hours/`.
- stderr: `failed to run git: fatal: 'main' is already used by worktree at '/Users/holdenhalford/Projects/work/brite-nites/britenites-claude-plugins'`.
- `gh pr view 309 --json state,mergedAt,mergedBy` returned `{state: MERGED, mergedAt: 2026-05-12T18:28:50Z, mergedBy: holdeeno}` — merge succeeded.
- `gh api -X DELETE repos/Brite-Nites/brite-claude-plugins/git/refs/heads/BC-6971/office-hours` returned 204 (deleted).
- `git fetch --prune origin` confirmed remote branch gone.

**Alternatives Considered:**
1. **Trust the merge + delete remote separately (chosen)** — minimal disruption. PR is already merged; only the local cleanup needs a different path.
2. `cd` to the primary repo to run cleanup there — rejected; wastes a directory swap mid-`/workflows:ship` and breaks the worktree-encapsulated session model.
3. Pre-emptively switch worktree to a non-main branch before merging — rejected; gh's local-cleanup expects HEAD to be on the merged branch in the worktree, not a different branch. The contention is structural (main is checked out elsewhere).

**Outcome:**
- PR merged at 2026-05-12T18:28:50Z. Remote branch deleted via gh api. Worktree removed via ExitWorktree.
- Pattern recurs every `/workflows:ship` from a worktree — surfaced this session for the first time during the post-PR-merge cleanup step.
- **Filed as memory gotcha:** `gotcha_gh_pr_merge_worktree_branch_delete.md` in user-level auto-memory.
