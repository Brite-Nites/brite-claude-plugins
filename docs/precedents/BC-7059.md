# BC-7059 — flow-architecture: `/flow:audit` smoke-test fixtures (clean + broken FDA shapes)

## task-1 — Deterministic-bash test harness for LLM-only slash command (first formal codification; extends `run-greenfield-vslice.sh` design)

<a id="BC-7059-task-1"></a>

**Decision:** When the target of a regression test is an LLM-only slash command (cannot be directly bash-invoked), structure the test as a deterministic-bash harness that re-implements the command's filesystem-only logic against fixture inputs, with explicit `skip-with-reason` for any phase that requires LLM dispatch, Linear MCP, or other non-headless surfaces. The fixtures themselves are the load-bearing artifact — reusable by future LLM-driven dogfood or v1.1 headless runners.

**Category:** pattern-application

**Confidence:** 9/10

**Inputs:**
- `/flow:audit` is a slash command — runs in LLM context, has no bash entry point. Naive interpretation of BC-7059's "invokes `/flow:audit`, asserts exit 0" would require an LLM round-trip per fixture, which CI cannot do.
- `plugins/flow-architecture/tests/run-greenfield-vslice.sh` (BC-7057) had established the design pattern informally — Section 1-5 test deterministic helper scripts; Section 6 is 8 explicit `skip "..." "..."` lines for the LLM-runner / Linear-MCP surface.
- BC-7059 § Out of scope explicitly defers "exhaustive per-gate coverage of all 35 Q29 gates" to parking-lot #52-#55, signaling the spec author understood and accepted the deterministic-subset framing.
- Independent post-PR reviewer (9/10 verdict) verified the design choice was correct and the skip-with-reason categorization was rigorous.

**Alternatives Considered:**
1. **Deterministic-bash harness + skip-with-reason for LLM/Linear (chosen)** — fixtures live at `plugins/flow-architecture/tests/fixtures/audit-{clean,broken}-shape/`; harness at `tests/run-audit-smoke.sh` re-implements Phase B gate logic in bash; Phase A deep / Phase C Linear-MCP / LLM-runner round-trip are 8 explicit `skip "..." "<reason>"` lines. The recognized-gate registry + `UNCATEGORIZED-GATE-FAIL` bucket guards against emitted-gate-ID drift.
2. **Drive an LLM round-trip from CI via `claude --print` or equivalent** — rejected: untenable in CI (cost, flakiness, model-pinning surface, no Linear creds in CI).
3. **Skip automated testing entirely; rely on BC-6998 Brand Hub dogfood** — rejected per the issue's "highest-leverage spot to add ONE automated smoke test" framing. Dogfood is rare (~once per release); a per-PR regression net is what catches the silent-corruption-of-every-ship-workflow failure mode.
4. **Mock the LLM by writing a Python stub that emulates `/flow:audit`'s output** — rejected: a mock that drifts from the real LLM behavior is worse than no mock at all (false-confidence). The deterministic-bash subset is testable directly against the same filesystem semantics the LLM evaluates.

**Outcome:**
- Files changed: `plugins/flow-architecture/tests/run-audit-smoke.sh` (382 LOC after simplify), fixture pair (28 markdown + 2 JSON + 2 stub-bash files), `.github/workflows/validate-plugin.yml` (new `audit-smoke-test` job advisory)
- Tests: 23 hard assertions pass / 0 fail / 8 skip-with-reason, exits 0
- CI: 4 jobs green (`validate`, `clone-drift-check`, `vslice-greenfield`, `audit-smoke-test`)
- Approved by: independent post-PR reviewer 9/10 CLEAR TO MERGE; primary review converged 0/0/0 at iter 3
- **Pattern now applies whenever a slash command needs regression coverage and the command itself is LLM-only.** Other v1.0 commands that could adopt this pattern: `/flow:office-hours` (project-intent interview — has heavy LLM coupling; partial deterministic subset = `intent.md` shape validator), `/flow:retro` (per-domain retrospective — partial deterministic subset = retro-doc shape + filesystem-canonical mirror at `docs/retros/`).

**Precedent Referenced:**
- `plugins/flow-architecture/tests/run-greenfield-vslice.sh` (BC-7057) — informal design precedent; this PR is the first formal precedent trace codifying the pattern.
- [BC-7057 task-2](BC-7057.md#BC-7057-task-2) — Q55 sub-decision 4 ("filesystem is source of truth") applied to test-report assertion counts. BC-7059 applies the same "filesystem is source of truth" framing to fixture content vs harness logic.

## task-2 — Literal-string-in-source AC anchor as drift-detection bucket (novel-pattern; 1st surface)

<a id="BC-7059-task-2"></a>

**Decision:** When an acceptance criterion requires that a class of bug remain detectable by the test, prefer a "literal-string-anchored bucket" pattern over a "count-based assertion." The AC reads `grep -q "BUCKET-NAME" path/to/test-script` against the script source; the runtime check verifies no evaluated result falls into `BUCKET-NAME`. Two-layer protection: (a) static grep catches accidental deletion of the registry mechanism itself, (b) runtime bucket catches drift in emitted-result-ID space.

**Category:** pattern-choice

**Confidence:** 8/10

**Inputs:**
- BC-7059 AC #5: `grep -q "UNCATEGORIZED-GATE-FAIL" plugins/flow-architecture/tests/run-audit-smoke.sh` (literal in script source).
- The smoke test's `RECOGNIZED_GATES` registry + `is_recognized_gate` predicate route any unrecognized gate-result-ID to the `UNCATEGORIZED-GATE-FAIL` bucket, which contributes to test failure.
- AC #5 is satisfied by the bucket name appearing 14× in the script (registry + emit_gate + assertion + comments).
- Independent post-PR reviewer flagged a real limitation: "this bucket catches drift in EMITTED-gate-ID space only. If `audit.md` adds a 36th canonical gate that this harness never emits, the registry silently stays stale and the test still passes." Documented as v1.1 parking-lot for shared JSON-manifest consolidation.

**Alternatives Considered:**
1. **Literal-string anchor + runtime bucket (chosen)** — combines static grep-ability with runtime drift detection. The literal `UNCATEGORIZED-GATE-FAIL` makes the discipline visible at grep-time; the runtime bucket enforces it.
2. **Count-based assertion** (e.g., `[ "$gate_count" -eq 19 ]`) — rejected. Hardcoded counts are brittle (require update on every registry add) and don't survive simplify-pass refactors that change emission cadence.
3. **Schema validator (jsonschema, etc.) against an external manifest** — rejected: stdlib-python only constraint + no shared manifest exists yet (`gates.json` is a v1.1 parking-lot candidate). The bucket pattern is the local approximation.
4. **No drift detection; trust manual review** — rejected: silent-drift is the failure mode the bucket exists to catch.

**Outcome:**
- Files changed: `plugins/flow-architecture/tests/run-audit-smoke.sh` (the bucket mechanism itself).
- The literal `UNCATEGORIZED-GATE-FAIL` string appears 14× in the script — registry constants, predicate, emit_gate path, two assertion call-sites (clean + broken), and explanatory comments anchoring the AC #5 + drift-detection rationale.
- **Reusable pattern**: any future regression test that protects a registry/manifest against silent drift can adopt the same "literal-string AC anchor + runtime bucket" recipe. Specifically applicable to: `_shared/four-mode-framework.md` mode taxonomy registry, `_shared/linear-writeback-pattern.md` type registry enum.
- **Documented limitation**: catches drift in emitted-result-ID space only, not registry-definition space. The script header (lines 35-58) explicitly names this as a parking-lot v1.1 candidate (consolidate gate registry into `skills/_shared/gates.json`).

**Precedent Referenced:**
- None — first surface of this specific pattern in the precedent corpus.

**Tags:** novel-pattern, ac-anchor, literal-string-in-source, drift-detection, registry-protection, bucket-classification

## task-3 — Independent post-PR reviewer fires reliably (6th surface; load-bearing canonical post-PR gate already promoted at 2nd surface BC-6977)

<a id="BC-7059-task-3"></a>

**Decision:** Independent post-PR reviewer in fresh context fires reliably for a 6th consecutive surface (BC-6959 → BC-6977 → BC-6961 → BC-6973 → BC-6971 → BC-7059). The pattern was promoted to LOAD-BEARING canonical post-PR gate at the 2nd surface (BC-6977); this surface is additional confirmation. Pattern: after primary `/workflows:review` converges and PR opens, dispatch a fresh general-purpose agent with no session context and instruct it to verify ACs independently + spot-check core correctness. Gate output: CLEAR TO MERGE or HOLD.

**Category:** pattern-application

**Confidence:** 10/10

**Inputs:**
- BC-7059's independent reviewer ran in fresh context, returned `CLEAR TO MERGE 9/10` after personally verifying all 5 ACs, spot-checking Phase B gate logic against `commands/audit.md` § Phase B + `_shared/artifact-gate-pattern.md`, spot-checking 2 fixture story-docs against harness regex predicates, verifying broken-fixture violations correctly localized, and confirming version-discipline (0.2.20 in both `plugin.json` + `marketplace.json`).
- Confidence held at 9/10 (not 10/10) for a defensible reason: "harness re-implements Phase B in bash rather than invoking `/flow:audit` itself; drift between bash impl and LLM slash command can only be caught by BC-6998 end-to-end dogfood." This is the kind of nuance a primary reviewer steeped in the spec might rationalize away.
- One transient API rate-limit on the first dispatch attempt (0 tool_uses, 1.7s duration); retry succeeded immediately. Pattern needs no compensation logic — just retry on transient errors.
- Surfaced via `/workflows:ship` Step 2 → independent-review call → merge gate. Total gate latency ~2 minutes incremental over baseline ship.

**Alternatives Considered:**
1. **Independent post-PR reviewer as merge gate (chosen)** — fresh context, no prior knowledge, hands-on verification of ACs + correctness spot-checks. Catches what primary reviewers rationalize away.
2. **Trust the primary review loop's convergence (iter-3 0/0/0)** — rejected; iter-3 0/0/0 confirms iter-2 fixes landed but doesn't catch novel angles a fresh reviewer would surface (e.g., the version-discipline cross-check, the bash-vs-LLM-slash drift framing).
3. **Skip independent review for "trivial" PRs** — rejected. Diff-triage classified this PR as TRIVIAL initially (21 net tracked LOC); the actual harness was 380 LOC of new logic. TRIVIAL verdicts are noisy enough that adopting a uniform "always independent-review post-PR" cadence has lower variance than a conditional one.

**Outcome:**
- 6th surface of the pattern (BC-6959 task-3 → BC-6977 task-3 → BC-6961 task-2 → BC-6973 task-2 → BC-6971 task-3 → BC-7059 task-3). Pattern was already promoted to load-bearing at BC-6977 (2nd surface); this surface continues to confirm under varied conditions: spec-heavy 9-sub-skill PR, 4-iter convergence with parallel-PR-double-rebase (BC-6977), spec-only diff with 2-iter convergence (BC-6971), test-only diff with 3-iter convergence + transient API rate-limit (BC-7059).
- Independent reviewer's "nice-to-haves" section surfaces a v1.0 / v1.1 drift framing the primary review didn't articulate ("harness re-implements Phase B in bash; drift only caught by BC-6998 dogfood") — useful for parking-lot triage post-merge.
- The pattern is robust under transient API rate-limits — single retry succeeds without state loss (new datapoint for this surface).
