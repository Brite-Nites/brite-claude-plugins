## Task 1 — Default-switch fallback paragraphs mirror sibling structure (2nd instance, emerging pattern)

**Category:** pattern-choice
**Confidence:** 6/10 (2nd instance of an emerging pattern; promotion at 4+ instances)
**Tags:** pattern-choice, default-switch-fallback, sibling-mirror, sprint-scoping, cadence-skill, emerging-pattern
**Precedent Referenced:** none (sibling-paragraph mirror is a new class — distinct from BC-5866 gate-respect surfaces, which govern orchestrator behavior rather than default rendering)

### Decision

When adding a new conditional-default ("default-switch") prose paragraph to `plugins/cadence/skills/sprint-scoping/SKILL.md` § 4 — i.e., a paragraph that says "the SQ is still asked but its `(Recommended)` default changes from X to Y given audit-card state Z" — mirror the structure of the existing accepted sibling: same trigger framing referencing `state.projects[i]._enrichment.<field>`, same render-switch sentence, explicit "no `skip_log` entry — this is a default-switch, not a skip" callout (because skip_log is reserved for actual question skips per the schema declaration at SKILL.md line 34), and same trailing parenthetical citation `(Closes BC-XXXX — codifies ... per docs/designs/cadence-orchestration.md § <N> <name> row)`.

**Important distinction:** default-switch fallbacks are NOT the same pattern class as gate-respect callouts (BC-5866 origin → BC-5864/5865/5872 instances). Gate-respect callouts use the `<!-- gate-respect: ... -->` HTML-comment header pattern and govern orchestrator behavior (forbidden improvisation patterns at AskUserQuestion gates). Default-switch fallbacks are inline prose that govern render-time defaults. The two surfaces are independent and accumulate separate instance counts.

### Surface in this session

BC-5900 added a "No-signal SQ1 fallback" prose paragraph to `plugins/cadence/skills/sprint-scoping/SKILL.md` § 4 (line 108). The existing "Scope candidate injection from enricher" SQ2-empty fallback (closes BC-5867) sits at line 99 — 6 lines above. The new paragraph was authored as a structural sibling.

**Initial pre-review draft included a `state.projects[i].skip_log = {question: "SQ1", reason: "no-signal..."}` log-line clause and inflated the precedent confidence to 9/10 by claiming continuity with the BC-5866 → BC-5870 task-1 gate-respect chain ("5th instance, arch-9 confirmed"). Both review agents independently flagged this as a problem:**

- **`skip_log` schema violation (P1, code-reviewer 9/10):** SKILL.md line 34 declares `skip_log = [string, ...]`. Existing string entries at lines 60, 88. The new object-shape entry violated the schema, and the BC-5867 sibling I claimed to mirror has no `skip_log` line at all (because it's a default-switch, not a skip). Fix: removed the `skip_log` clause entirely and added an explicit "no `skip_log` entry — this is a default-switch, not a skip" callout to the new prose. The mirror is now genuinely structural (matches the BC-5867 sibling in shape).
- **Promotion-chain category error (P3, code-reviewer 7/10):** the gate-respect chain (BC-5866 origin → BC-5864/5865/5872 instances → BC-5870 task-1) is a different pattern class from default-switch fallback paragraphs (BC-5867 → BC-5900). They share no promotion lineage. Fix: rescored to 6/10, dropped the BC-5870 task-1 citation, scoped the precedent to its true class (default-switch fallback mirroring at N=2).

### Pattern

**Sibling-paragraph mirroring at N=2 is an emerging pattern, not a load-bearing one.** At N=2 the precedent is descriptive — it captures a sensible local convention (any new default-switch should look like the existing one). At N=3-4 it accumulates evidence as a class. Only at N=4+ does the mirror become load-bearing in the sense that a divergence is visible-at-a-glance and consumer code reads all instances the same way. Premature promotion to "load-bearing" misallocates pattern-evolution budget — every "5 instances → arch-9" claim should be auditable against actual prior surfaces of the same class, not surfaces of an adjacent class.

### Applies when

- Adding any new default-switch fallback to `plugins/cadence/skills/sprint-scoping/SKILL.md` § 4 (BC-5901 ritual-close-out SQ2–5 will likely be the 3rd instance — but 4 simultaneous Q-row defaults may instead favor a single per-question table over 4 prose paragraphs)
- Distinguishing default-switch fallbacks (inline prose, render-time) from gate-respect callouts (HTML-comment headers, orchestrator-time) when authoring or reviewing skill markdown

### Follow-ups

- BC-5901 will be the 3rd instance — observe whether it adopts 1 mirror paragraph + table or fans out to 4 mirror paragraphs (one per Q2/Q3/Q4/Q5)
- At a 4th-instance default-switch ship (likely linear-housekeeping § 4 mutation-skip defaults or narrative-writer voice-guard defaults), reassess promotion to pattern-application 7/10 + cadence/CLAUDE.md gotcha extension
- **Meta-precedent (this fix):** premature precedent promotion is itself a recurring failure mode; both review agents catching a category-error promotion in a pattern-mirror precedent is evidence that promotion claims need the same verify-cited-precedent treatment BC-5953 task-2 captured for review-validators (live-verify every "Nth instance" claim against the actual prior precedents' tags + decisions)

## Task 2 — Forward-pointer parenthetical bridges declarative spec to conditional override

**Category:** pattern-choice
**Confidence:** 7/10 (new pattern; first instance — high confidence because the failure mode is concrete and recurrent)
**Tags:** pattern-choice, forward-pointer, spec-bridge, declarative-vs-conditional, drift-prevention, cadence-spec
**Precedent Referenced:** none (new pattern; informally co-applied with BC-5870 / BC-5871 § 1.6 reconciliation rendering)

### Decision

When a § 2.3-style adaptivity row introduces a conditional override on top of a § 2.2-style declarative default, **also touch the § 2.2 declarative line with a forward-pointer parenthetical** in the form `*(or "<new default>" when <condition> — see § 2.3 <row name> row)*`. The parenthetical lives inline in the declarative spec's "Default:" sentence, before the "Escape:" clause. Without this bridge, a future reader sees an unconditional default in § 2.2 and a conditional override in § 2.3, can legitimately argue the spec is internally inconsistent, and may file it as a P2 ("spec-strict conflict — § 2.2 says X, § 2.3 says Y").

### Surface in this session

BC-5900's § 2.3 6th-row addition forced the question. § 2.2 Q1 read: *"Default: agent proposes from top-priority carry-over + top-priority backlog candidates. Escape: custom sentence, or mark project parked."* — strictly unconditional. The new § 2.3 row introduced a conditional override. I added the parenthetical directly: *"Default: agent proposes from top-priority carry-over + top-priority backlog candidates *(or 'Owner picks next track — free-text' when both are empty — see § 2.3 no-signal row)*. Escape: ..."*. Plan called it out explicitly to prevent the future-reader-files-P2 failure mode that BC-5900 itself was an instance of (§ 2.2 Q1 strict-default → AC #1 breach when no signal exists → P2 → spec-codification fix).

### Pattern

**The bridge is the same shape as BC-5870/BC-5871's § 1.6 rendering rule** — both are "the declarative rule has a conditional override; surface the override at the declarative site so a reader can't reach the wrong conclusion from the declarative site alone." The pattern compresses to: *every § 2.3-style adaptivity row that overrides a § 2.2-style default also touches the § 2.2 line with a parenthetical pointer.*

### Applies when

- Adding any new § 2.3-style row to `docs/designs/cadence-orchestration.md` that overrides a § 2.2 default
- By extension: any spec doc with a "general rule" section + an "exceptions/overrides" section (where the general-rule section is read more often)
- BC-5901's ritual-close-out SQ2–5 row will need 4 forward-pointer parentheticals (one per Q2/Q3/Q4/Q5) — making the recipe mechanical at first sibling

### Follow-ups

- BC-5901 is the validation case — if the recipe holds for 4 simultaneous Q-row touches, promote confidence to 8/10 and add to cadence/CLAUDE.md gotchas
- If an instance in a non-cadence spec doc applies (workflows or marketing skill specs grow a § X.3-style overrides table), promote to architecture-7
