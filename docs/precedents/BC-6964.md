## task-1 — Memory-mirror citation drift: cite from in-repo canon, not the brite-base auto-memory mirror

**Pattern type:** pattern-choice (NEW — 1st surface)

**Confidence:** 9/10

**Context.** When implementing add-domain.md I derived 17 `memory:NNN` citations from `~/.claude/projects/-Users-holdenhalford-Projects-work-brite-nites-brite-base/memory/project_fda_plugin_interview.md` (the auto-memory mirror) because that file was loaded into context at session start and was convenient to read. The in-repo canonical version at `plugins/flow-architecture/docs/design-rationale/project_fda_plugin_interview.md` is the authoritative source — and it had advanced 2-14 lines beyond the mirror due to recent amendments (Q23 amendment 1, Q47 amendment 1, etc.). Iter-1 code-reviewer P2 conf 9 surfaced the systematic drift across all 17 citations.

**Decision.** Always cite `memory:NNN` from the **in-repo canonical interview file**, never from the auto-memory mirror. Rationale:
1. The auto-memory mirror lags amendments — it's updated only when a session explicitly writes to it, not when the in-repo canon is amended.
2. Future readers of the orchestrator MD resolve `memory:NNN` against the in-repo path (which is what the orchestrator's `See also` block + the agent dispatch matrix point at). Citing from the mirror creates a phantom resolution target.
3. The in-repo file is the source-of-truth per the plugin CLAUDE.md "When in doubt, read the Q-lock entry, not this file" rule (which transitively rules in-repo > mirror).
4. Catch cost: iter-1 review surfaced 17 corrections via direct canon spot-read — relatively cheap to fold in, but the precedent prevents the cost from recurring.

**Rejected alternatives:**
- Sync the auto-memory mirror to in-repo before drafting: would require a sync-discipline pre-flight step every session; brittle.
- Annotate citations with both sources: noisy, doubles the citation surface.
- Live with the drift: would re-surface as a P2 every implementation session for the foreseeable future.

**How to apply.** Before citing `memory:NNN` in any plugin artifact (orchestrator MD, skill body, agent definition, precedent trace), open the **in-repo** canonical file at `plugins/flow-architecture/docs/design-rationale/project_fda_plugin_interview.md` (or the equivalent canon for the plugin) and grep for the cited content. Do not cite from the auto-memory mirror at `~/.claude/projects/-Users-holdenhalford-Projects-work-brite-nites-brite-base/memory/`. The mirror is for LLM-session-context loading only, not for citation derivation.

**Telemetry watch.** Look for this pattern to surface in BC-6996 (plugin CLAUDE.md), BC-7057 (vertical-slice integration test), and any future FDA artifact that cites canon. Promotion threshold: 3 surfaces. Joint promotion candidate with the BC-6965 task-1 / BC-6963 task-1 cluster (precedent-fix-extension to canon) — both extend faithful-echo discipline from "matching the canon's literal text" to "matching the canon's current line numbers." If a future session caches the orchestrator-side citation map as a `_shared/` reference (e.g., `_shared/q-lock-line-anchors.md` regenerated by a script), that promotion would close this pattern.
