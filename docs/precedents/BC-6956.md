## Task 1 — Conservative read-contract for filesystem state files with Q-locked paths

| Field | Value |
|---|---|
| **Decision** | When a state-file path is Q-locked (`docs/plans/.flow-phase-state.json` per Q31.4) but the Q-decision doesn't specify behavior on malformed JSON, the reader should soft-fail with sentinel values (`STATUS=unknown / STALE=yes / STALE_REASON=parse-error`) + stderr warning + exit 0 — NOT hard-exit. Callers fall through to artifact-driven classification (the next-strongest signal) instead of bricking the orchestrator on a single corrupted file. |
| **Category** | pattern-choice |
| **Confidence** | 9/10 |
| **Precedent Referenced** | None (new class for the codebase precedent record) |

**Inputs**
- Q31.3 enumerates stale conditions (`>7 days` OR `status=completed` OR `status=abandoned`) but is silent on malformed-JSON behavior
- Q12.3 mode-classification has a documented fall-through ("Stale or non-in_flight breadcrumb → fall through to artifact-driven classification") but the previous `cmd_read` hard-exited with `exit 3` on parse failure, blocking the fall-through under `set -euo pipefail`
- Code-reviewer P1 finding (9/10 confidence) with end-to-end reproduction: full FDA artifacts + malformed `.flow-phase-state.json` → exit 3, no mode emitted, instead of the documented `incremental-add` classification

**Alternatives Considered**
1. **Chosen** — Modify `cmd_read` to soft-fail with sentinel `STATUS=unknown / STALE=yes / STALE_REASON=parse-error` + stderr diagnostic + exit 0. Single-source-of-truth fix: every caller (current + future) gets the safe semantics without each having to add an `if !` gate.
2. Rejected — Gate every callsite with `if !` and treat parse-failure as fall-through. Pushes responsibility to N callers (currently 1, eventually 5+ per Q30.6 sub-skill consumers); easy to miss in future code; subtler invariant to maintain.
3. Rejected — Leave cmd_read strict and document that callers must catch the exit. Status quo; the bug ships.

**Outcome**
- Adopted (1). cmd_read now emits 5 fields (`STATUS=unknown / LAST_UPDATED= / STALE=yes / STALE_REASON=parse-error` + the leading `EXISTS=yes`) on parse failure + stderr warning. Independent Opus validator confirmed reproduction + fix correctness.
- Bonus P3s piggybacked into the same rewrite: unparseable `last_updated` now marks `STALE=yes / STALE_REASON=timestamp-unparseable` (was silent fresh); embedded newlines in `status` / `last_updated` are sanitized before emission (preserves KEY=VALUE per-line contract).

**Generalization**: For any state file whose path is locked by a Q-decision but whose error-mode behavior isn't, the read-contract should default to "emit a sentinel that signals fall-through is appropriate" rather than hard-exit. Specifically: malformed JSON → `STALE=yes / STALE_REASON=parse-error`; unparseable timestamp → `STALE=yes / STALE_REASON=timestamp-unparseable`; embedded control chars in values → sanitize. The pattern transfers to: cadence `.cadence-phase-state.json` reads, any future `.flow/config.json` reader (already applied symmetrically in this same PR), and any sub-skill that reads a Q-locked artifact whose absence-vs-corruption distinction shouldn't brick the caller.

## Task 2 — `mktemp "${path}.tmp.XXXXXX"` for symlink-safe atomic-rename writes

| Field | Value |
|---|---|
| **Decision** | When implementing the atomic-rename + parse-verify pattern (Q31.5) for state-file writes, use `mktemp "${path}.tmp.XXXXXX"` to create the staging file in the same directory as the final target, instead of the deterministic `${path}.tmp` suffix. Same directory keeps the subsequent `mv` a same-filesystem (atomic) rename; mktemp's `O_CREAT \| O_EXCL` semantics + mode 600 + random 6-char suffix defeat hostile pre-staged symlinks at the predictable path. |
| **Category** | pattern-choice |
| **Confidence** | 8/10 |
| **Precedent Referenced** | None (new class) |

**Inputs**
- Q31.5 locks "atomic-rename + parse-verify + content-match" but doesn't specify tmp-file naming
- Security-reviewer P3 (downgraded from P3 7/10): a hostile pre-staged symlink at `${path}.tmp` pointing to a sensitive file (e.g., `~/.ssh/authorized_keys`) would be followed by `cat > "$tmp"`, overwriting the symlink target
- Threat model: shared dev box, CI runner, or malicious checkout where attacker has write access to `docs/plans/` but the user is running the writer

**Alternatives Considered**
1. **Chosen** — `mktemp "${path}.tmp.XXXXXX"`. `mktemp` creates the file atomically with `O_CREAT | O_EXCL`-equivalent semantics; the random suffix defeats remote prediction; the file is created with mode 600 so even if the attacker can read the directory they can't read tmp contents.
2. Rejected — `mktemp -d` + write inside the tmp dir + rename out. Adds a dir to clean up; harder to reason about atomic semantics across the dir + file pair.
3. Rejected — `set -C` (noclobber) + open via shell redirection on a deterministic name. Catches a pre-existing file but not a pre-existing symlink.
4. Rejected — Status quo (`${path}.tmp`). Ships the symlink-preempt attack window.

**Outcome**
- Verified end-to-end (scenario S21 in BC-6956 smoke test): a pre-staged symlink at `${path}.tmp` is bypassed; the writer picks a unique suffix that doesn't collide; the target file gets the intended JSON contents; the orphaned symlink stays in place (harmless).
- Same-directory placement preserves `mv` atomicity (POSIX guarantee on same FS).
- The change required a corresponding rewrite of cleanup logic (explicit `if !` checks around `mv` with `rm -f "$tmp"`) because the previous code relied on the deterministic name to refer back to the tmp file in error paths — `mktemp` returns the path in a variable, so error paths must reference `$tmp` directly. That rewrite also fixed P2-B (mv-failure orphan-tmp leak).

**Generalization**: Any bash script that implements the atomic-rename pattern for a user-facing state file (cadence `.cadence-phase-state.json`, any future `.flow/config.json` writer, deploy scripts that write `.last-deploy.json` to a known path, etc.) should use `mktemp "${path}.tmp.XXXXXX"` instead of a deterministic `${path}.tmp` suffix. The tradeoff is one extra subshell at write time vs. closing the symlink-preempt attack class. For state files written once per phase transition (cold path), this is the right tradeoff every time.

## Task 3 — Hot-path latency diagnosis via PATH-strip benchmarking

| Field | Value |
|---|---|
| **Decision** | When an interactive-hot-path script invokes an external CLI tool (`gh`, `git`, `jq`, etc.) and the tool's wall-clock cost is suspected to dominate the script's runtime, diagnose with the PATH-strip pattern: run the script twice, once with the tool on PATH and once with it removed (`PATH=/usr/bin:/bin <script>`), and compare wall-clock medians. The delta isolates the tool's cost from the rest of the script's work. If the delta exceeds an observable threshold (≥200ms for an interactive script), file as P1. The fix pattern: env-var cache passthrough (orchestrator probes once per session, exports cache var, children skip the probe). |
| **Category** | pattern-choice |
| **Confidence** | 7/10 |
| **Precedent Referenced** | None (new class for measurement methodology) |

**Inputs**
- Performance-reviewer flagged `gh auth status` at `flow-context-load.sh:73` as P1 9/10 with measured ~410ms median delta
- Independent Opus validator reproduced: 0.45s with `gh` on PATH, 0.04s without, delta ~410ms median
- The orchestrator runs once per sub-skill preamble (5–10 sub-skills per FDA session); 5× 410ms = 2.05s of pure auth-probe latency per session, none of it informative within-session
- `gh auth status` hits the OS keychain + (depending on `gh` version) a token-validity GraphQL ping — fundamental to the tool, not optimizable in-place

**Alternatives Considered**
1. **Chosen** — `FLOW_GH_AUTH_CACHE` env passthrough (mirrors the `FLOW_SHAPE_CACHE` pattern shipped one iter earlier). Orchestrator probes `gh auth status` once at session start; children inherit `FLOW_GH_AUTH_CACHE=yes|no` and skip the per-call probe. Standalone callers still fall through to a direct probe. Invalid cache values warn + re-probe.
2. Rejected — Cache to a disk file with a TTL. Adds filesystem state, TTL invalidation policy, cleanup. Env-var is sufficient for session-scoped caching and naturally invalidates on session end.
3. Rejected — Probe lazily only when downstream consumers need GitHub. The preamble's role is to emit ground-truth signals for sub-skills; lazy probe would push the cost from "preamble emit" to "first GitHub-using sub-skill", which is worse UX (delay surfaces during action, not setup).
4. Rejected — Read `~/.config/gh/hosts.yml` directly instead of invoking `gh`. Skips token-validity check, which is exactly the value `gh auth status` provides. Lower-cost but lower-correctness.

**Outcome**
- Measured 0.464s → 0.051s (~9× speedup) with `FLOW_GH_AUTH_CACHE=yes` set.
- Independent perf validator's measurement methodology (`PATH=/usr/bin:/bin time <script>`) cleanly isolated the offending tool's cost from the orchestrator's other work, without instrumenting the script itself.
- The fix shape (env-var cache passthrough) was identical to `FLOW_SHAPE_CACHE` from the prior iter, suggesting this is an emerging plugin-orchestrator pattern: "Probe expensive thing once at the orchestrator; pass result down via env to children."

**Generalization**: The PATH-strip benchmark is a low-instrumentation way to attribute wall-clock cost to a specific external CLI invocation in any bash orchestrator script. Generalizes to any hot-path script that invokes `git`, `jq` (when unavoidable), `sf`, `aws`, `kubectl`, etc. When the delta exceeds the action's "feels instant" threshold (~100-200ms interactively), the fix is almost always an env-var-cache passthrough rather than caching at the CLI tool's own layer (which often isn't possible). Pattern is now proven twice in this plugin (FLOW_SHAPE_CACHE + FLOW_GH_AUTH_CACHE); the third instance (TBD; candidate: `git rev-parse --show-toplevel` if it ever ranks) would promote this to a load-bearing plugin convention.

## Compounds

- **Task 1 generalizes the "soft-fail with sentinel + STALE_REASON" pattern** to any Q-locked state-file reader. The reader-side symmetry with the writer-side `set -C` / `mktemp` defense (Task 2) means a corrupted file at the Q-locked path now has consistent end-to-end handling: writes never produce a corrupt file (parse-verify + content-match before promotion); reads gracefully fall through if a corrupted file does land via some other channel (manual edit, partial write from a non-FDA tool, etc.).
- **Task 3's "env-var cache passthrough" pattern** has now landed twice in `plugins/flow-architecture/` (FLOW_SHAPE_CACHE in iter-1 simplify, FLOW_GH_AUTH_CACHE in iter-1 P1 fix) plus a parallel-shape `_FLOW_SHAPE_*` individual-var variant for cases where the bulk-blob form pays additional parse cost. A third instance would justify naming the pattern in plugin CLAUDE.md (Q55 spinoff candidate) and the FDA `_shared/` utilities (BC-6955 surface).
- **Review-iteration convergence count (4 iters: simplify → P1 → P2/P3 + filtered → perf-polish)** suggests the `/workflows:review` loop benefits when the orchestrator proactively folds parallel instances of a flagged anti-pattern in the same iter. Iter 4 collapsed all 3 remaining `printf | sed` re-parse sites at once after iter 3 fixed just CONFIG_OUT; iter 4 came back 0/0/0 across 3 reviewers. If iter 3 had folded all 4 sites (CONFIG_OUT + SHAPE_OUT × 2 + BC_OUT) proactively, we'd have converged in 3 iters. Lesson: when a reviewer flags an anti-pattern, grep for parallel instances before applying the fix.
