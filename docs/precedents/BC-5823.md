# BC-5823: Handbook-canon-first for scope decisions touching verticals, ICPs, or personas

**Date:** 2026-04-20
**Category:** pattern-choice
**Confidence:** 8/10

## Decision

When a Linear issue body prescribes domain scope (specific verticals, ICPs, personas, offer names) and a handbook canonical reference exists for the same domain, read the handbook FIRST, compare, and treat any discrepancy as a scope question that requires user approval to resolve. Handbook canon wins by default. The issue body is a proposal; the handbook is the source of truth for what Brite actually serves.

## Context

BC-5823 was a content port from upstream `Revgrowth1/ai-gtm-workflows` (MIT). The issue body named 3 Brite-entity industry tables to add to `hidden-signals-library.md`:

- Entertainment Venues (Brite Labs)
- Landscape / Hardscape Contractors (Brite Supply)
- HOAs / Property Management (cross-motion)

Mid-execution, after drafting the first 21 signal rows using generic definitions of each vertical, the user rejected the draft: _"no these are mostly wrong actually, and they don't actually take into account our verticals / ICPs / Personas."_ The rejection triggered a handbook read against `Brite-Nites/handbook@main:marketing/go-to-market/verticals/README.md`, which revealed the canonical 23-vertical taxonomy.

Three discrepancies surfaced:

1. No canonical "Entertainment Venues" vertical — the closest handbook verticals (Event Venues, Sports Stadiums, Theme Parks) are separate and all status **Exploring** or **Future** with no ship-ready ICP docs.
2. **Brite Supply verticals are explicitly deferred** from the 23-vertical taxonomy: _"Brite Supply verticals (professional installers, property management) deferred — Supply's GTM motion is different enough to handle separately."_
3. Only HOAs matched — the other two were proxies for absent taxonomy entries.

After presenting the handbook-canon alternative (Municipalities / HOAs / Universities — the 3 handbook-Active verticals with ship-ready ICP + persona docs), the user approved the swap on 2026-04-20.

## Alternatives Considered

1. **Ship the issue-body verticals verbatim.** Rejected — user had already flagged that generic-vertical rows miss the ICP/persona lens. Shipping as-drafted would produce Brite-entity tables that no handbook-anchored skill could dereference reliably.
2. **Ship the issue-body vertical headings but anchor rows to the nearest handbook vertical (e.g. "Entertainment Venues" headed with rows sourced from Event Venues playbook).** Rejected — misleading headers force downstream skills to carry a translation layer between signal-table name and playbook name.
3. **Swap to 3 handbook-Active verticals — Municipalities / HOAs / Universities — and document the departure (chosen).** Accepted. Each ported signal row anchors to a specific handbook trigger (offer page, persona, procurement/budget cycle). Downstream skills (account-research, situation-mining, creative-angles, tam-mapping, campaign-debrief) read the same signals the handbook already validates.

## Outcome

Delivered `plugins/marketing/references/` — 22 files (16 research-processes + 3 top-level refs + UPSTREAM.md + README.md + plan) porting upstream at pinned SHA `03b30e1`. Three documented departures from the issue body:

1. **Serper → WebSearch translation is prospective-only.** Upstream had zero Serper mentions at pinned SHA. Rule codified in `UPSTREAM.md` for future pulls.
2. **Vertical swap** (this precedent).
3. **Ported 10 upstream industry tables instead of the 7 named in the issue** — conservative expansion satisfies the `≥10 industry headings` verification criterion more robustly.

`/workflows:review` verdict: TRIVIAL (content-only port, no code logic, 2,810 lines markdown). 0 errors / 0 guardrail violations. Merged as PR #146.

**Reusable beyond this case.** The pattern applies to any future scope decision where the issue body names domain entities (verticals, ICPs, personas, offers, campaign types, channels). Sequence:

1. Before drafting domain content, fetch the handbook's canonical reference via `gh api repos/Brite-Nites/handbook/...` — Context7 does not resolve the private handbook, per `reference_handbook_access.md`.
2. Compare issue-body entities to handbook entities by name.
3. If any issue-body entity is missing from handbook canon OR the handbook explicitly defers its domain, surface the discrepancy to the user **before** drafting content — not after.
4. Document the approved departure in the PR body + the domain artifact's meta-doc (UPSTREAM.md, README.md, or equivalent).

**Secondary observation.** The "draft content, get rejected, re-read handbook, re-draft" loop cost roughly 15 minutes of wasted work (21 rows written that never shipped). A pre-draft handbook read would have saved that turn. The trigger to remember: the phrase "this issue touches verticals / ICPs / personas / offers" is the cue to handbook-first, not issue-body-first.

**Tertiary observation.** The issue body that prescribed the wrong verticals was itself a product of a prior scoping session (`docs/plans/marketing-gtm-expansion.md` §1.1) that didn't cross-check handbook canon during upstream deep-dive. Scoping docs are not handbook-authoritative — they're proposals that still need handbook verification before any domain-specific Linear issue gets filed. Worth considering a handbook-check gate in `/workflows:scope` for issues that touch domain content.
