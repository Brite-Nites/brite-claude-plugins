# BC-5793: First-of-N Phase 3 skill customization — locks the template for 12 siblings

**Date:** 2026-04-20
**Category:** pattern-choice
**Confidence:** 9/10

## Decision

When a milestone has N parallel issues with the same shape (here: 13 Phase 3 "customize sf-X" skill issues, BC-5793 through BC-5805), the first-of-N session carries disproportionate weight. Treat every decision the first session makes — attribution wording, cross-ref format, references/ scope, frontmatter conventions, departure-flagging pattern — as a template for the other 12, not a one-off choice. Surface every cross-issue convention conflict at the Plan gate and resolve it in a way that updates the shared convention source (UPSTREAM.md here), not just the current skill.

## Context

BC-5793 was the first Phase 3 skill customization in the RevOps milestone. The issue body prescribed several patterns (rename `sf-X` → `brite-X`, attribution header wording, verify-table shape) that would repeat verbatim across BC-5794–BC-5805. Three conflicts surfaced during Explore/Plan:

1. **Rename vs keep upstream name.** Issue title said rename; ADR-007 §3.6 (locked 2026-04-19, *after* the issue was filed) said keep upstream names. Per-sibling ADR-vs-issue re-litigation would waste 12 sessions.
2. **Attribution wording.** Issue T2 grep: `"Adapted from Jaganpro"`. Prescribed header block: `"# Brite-customized from Jaganpro/sf-skills@<sha>"`. UPSTREAM.md (written in BC-5789): `"Brite-customized from..."`. Three sources, two wordings.
3. **Cross-refs to planned commands.** Issue body said reference `/revops:deploy-sandbox` and `/revops:deploy-prod`; those commands don't exist yet (BC-5790/5791 Todo). Same forward-ref question will hit every Phase 3 skill.

## Alternatives Considered

1. **Treat BC-5793 as a one-off and make local decisions.** Rejected — each of the 12 siblings would re-derive the same decisions from scratch, burning ~6 AskUserQuestion gates × 12 = 72 redundant decisions. Drift risk high (sibling-N ships with one attribution format, sibling-M with another).
2. **Escalate all three conflicts before implementing anything.** Rejected — the answers are already in ADR-007 (§3.6) and the issue body (T2 grep wording). What's missing is a shared convention source that reflects the resolutions. Escalation would produce the same outcome as fixing UPSTREAM.md + updating the attribution header once.
3. **Resolve each conflict at the Plan gate in BC-5793 + update the shared convention source (chosen).** Keep `sf-deploy/` name; standardize attribution to `"Adapted from Jaganpro/sf-skills@ff1ab74"` (matches T2, propagates to all 13 siblings via UPSTREAM.md update in this PR); carry forward-refs with "(planned — BC-XXXX)" note. Document all departures in commit body + PR description + Linear comment per the BC-5758 3-location audit-trail pattern.

## Outcome

Delivered `plugins/revops/skills/sf-deploy/` customization with 5 departures from issue body, all locked at Plan gate via AskUserQuestion. Updated `plugins/revops/UPSTREAM.md` attribution convention in the same PR so the 12 sibling skills inherit the corrected wording. Forward-ref pattern `(planned — BC-XXXX)` carried for 3 cross-refs (deploy-sandbox/deploy-prod/post-deploy-runbook). Verify-table adapted — T1 flipped from "brite-deploy exists" to "sf-deploy exists, brite-deploy does not" per ADR-007 §3.6.

All 10 objective tests passed (T1-T5, T8-T10); T6/T7 deferred to cross-repo manual check post-merge. `/workflows:review` verdict: TRIVIAL (markdown-only, no logic/config touched).

**Reusable beyond this case.** Any milestone with N parallel same-shape issues should identify the first-of-N session and use it to lock shared conventions. The departure-approval-at-Plan pattern (from BC-5758) combined with shared-convention-file update (new here — UPSTREAM.md) keeps the remaining N-1 sessions mechanical.

**Sub-pattern captured:** When convention drift is surfaced between an issue body, a locked ADR, and a shared convention file (here UPSTREAM.md), update the convention file in the current PR rather than deferring. The next session will otherwise re-surface the same conflict and either re-resolve it (wasted turn) or drift silently.

**Strengthens** BC-5758 precedent by adding the shared-convention-source update to the 3-location audit trail.

**Precedent Referenced:** BC-5758 (3-location audit trail for Plan-gate departures)
