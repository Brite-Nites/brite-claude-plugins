## Task 1 — Fix-shape vs root-cause diagnostic at plan-gate (reframe-at-analysis)

**Date:** 2026-05-01
**Category:** scope-change
**Confidence:** 7/10
**Tags:** plan-gate, factual-anchor-recipe, scope-change, root-cause, issue-reframe

### Decision

When an issue body's "Recommended fix" section is plausible but the prescribed fix shape lives in the same file/skill as the issue title implies, run a fix-shape vs root-cause diagnostic before plan-write: trace the root cause backward through the layers of the system, then check whether the prescribed fix actually addresses the root cause or just the symptom. If the fix and root cause live in different files/levers, surface the reframe to the user before committing to the original framing — even if it means filing new tickets and superseding the original.

For BC-6549: issue body framed the work as "audit + rewrite 14 marketing skill templates so sentences read OK when tokens render as empty." Start of analysis revealed the high-risk tokens (`RECENCY_ANCHOR`, `PROOF_POINT_*`, `INITIATIVE_NOUN`) ARE the content of their sentences — no rewrite makes them graceful when missing. Walking the rendering layers backward (per-lead value → campaign-level default → empty string) showed the actual lever was upstream: the `launch-campaign.md` Phase 1 step 5 validation gate that checks for non-empty `custom_variables[].default` but is currently warn-and-override. Reframe surfaced to user, escalated to Holden for sign-off (who confirmed and added the long-term smart-merge formula concept), then BC-6549 closed and split into BC-6556 (near-term backstop, this issue) + BC-6557 (long-term research).

### Alternatives Considered

1. **Reframe + file new tickets + close BC-6549 as canceled** *(chosen)* — accurate ticket framing for the fix shape (validation-gate tightening lives in launch-campaign, not email-copywriting). Two tickets keep near-term and long-term separated. Higher bookkeeping cost (~5 min) but durable audit trail. Round-4 dogfood (BC-6554) dependency swapped to the new ticket.
2. **Update BC-6549 body to reframe + ship under same ticket** — rejected. Issue title still says "email-copywriting templates should degrade gracefully" but the fix lives in launch-campaign. Future readers grepping the chain history would be confused by the title-vs-fix-shape mismatch.
3. **Ship under BC-6549 with a comment explaining the reframe** — rejected for the same title-vs-fix-shape reason.
4. **Close BC-6549 as won't-do; skip the near-term fix entirely** — rejected. The fail-closed gate is a real backstop with clear value (stops broken-syntax sentences from reaching production). Skipping it just because the long-term direction is bigger would leave the gap open until BC-6557 ships, which is research-then-build (months).
5. **Ship the issue-body-prescribed template restructure** — rejected. Confirmed during analysis: load-bearing tokens can't be made graceful by sentence rewrites. Would have spent ~30 min editing 30 files for ~zero durable value.
