# BC-5796: Sibling-three confirms template durability; pre-merge review catches the BC-5795 factual-error class cheaply

**Date:** 2026-04-20
**Category:** pattern-choice
**Confidence:** 7/10

## Decision

For a templated N-sibling series, the third execution is where the template either proves durable or collapses. Ship sibling-three mechanically with zero Plan-gate re-derivation — inheriting BC-5793's first-of-N decisions verbatim and BC-5794's "no re-litigation" rule and BC-5795's post-merge-review lessons — and use the session to validate that pre-merge review catches the same factual-error class that BC-5795's revert+reship pattern was designed for, at a much lower cost (one edit vs. a revert commit + second PR).

## Context

BC-5796 customized `plugins/revops/skills/sf-apex/SKILL.md` with 12 Brite Apex conventions. It was the third Phase 3 RevOps skill customization, following BC-5793 (first-of-N, sf-deploy) and BC-5794 (sibling-one, sf-permissions) and BC-5795 v2 (sibling-two, sf-connected-apps, the revert+reship case).

All five BC-5793 departures from the issue body (keep upstream name, no `git mv`, T-path flips) applied verbatim. No AskUserQuestion was needed at Plan gate for those overrides — a deliberate test of BC-5794's "no re-derivation on templated work" rule. Template variant B (Brite sections BEFORE `## When This Skill Owns the Task`) was chosen without re-litigation, making it the majority placement at 3-of-4.

Pre-merge review (`/workflows:review`, thorough, 4 agents: code, security, performance, cdr-compliance) surfaced 0 P1, 0 P2, 5 P3. Independent Sonnet verifier CONFIRMED 3 of 5. The top-confidence (9/10) finding was exactly the BC-5795 class: a factual count error ("22 gotchas" in the See-also bullet when the actual bullet count in `brite-salesforce/CLAUDE.md` §Apex & Automation lines 175-196 is 20). The two DISMISSED findings were also instructive — one (Rule 11 Guest User claim) matched the upstream source verbatim, so the inaccuracy lives at brite-salesforce/CLAUDE.md line 196, not in this customization.

All three confirmed P3s were fixed in the same branch before PR opened. The PR (#153) shipped with 0 P1/P2/P3 known issues.

## Alternatives Considered

1. **Re-run Plan gate on the five departures.** Rejected — BC-5794 precedent exists precisely to skip this on sibling-one-onward. Re-running would burn 4–5 AskUserQuestion turns on decisions already ratified. The cost of the test is paid once (sibling-one); every subsequent sibling is meant to consume the outcome, not re-test the decision.

2. **Ship without running `/workflows:review` — trust the template.** Rejected — BC-5795 showed the template does NOT catch factual errors in load-bearing content, because the template is about structure + conventions, not about content truth. The 22→20 gotcha count would have slipped through to merge, then been caught by a future `/workflows:review` as a P1-level factual error in agent-invoked content, which per BC-5795 triggers the revert+reship protocol. Pre-merge review is the right-cost instrument: ~1 P3 fix vs. a revert commit + reopened PR.

3. **Run `/workflows:review` pre-merge as BC-5796 did (chosen).** Pre-merge review turned what would have been a BC-5795-class post-merge revert into a single edit. Net: template durable, factual-anchor discipline validated at lower cost, BC-5795's precedent refined (revert+reship is for cases review missed, not for cases review can catch at any phase).

## Outcome

Delivered `plugins/revops/skills/sf-apex/SKILL.md` customization + `docs/plans/BC-5796-plan.md` as a single commit → PR #153. Review verdict NON-TRIVIAL; 3 P3 fixes applied in the review loop, 2 dismissed by validator. `/workflows:review` did catch the one BC-5795-class factual error at P3 severity pre-merge — if it had slipped to merge, the revert+reship protocol would have fired per BC-5795.

**Reusable beyond this case.** Sibling-three is the right inflection point to declare a template "durable" rather than just "validated." BC-5794 confirmed sibling-one could pick up sibling-zero's template. BC-5795 tested the template under pressure (P1 factual errors post-merge, revert+reship fired). BC-5796 shows the template holds with the discipline integrated: factual-anchor citations at Plan, review run pre-merge, verifier-corroborated P3 fixes applied inline. The remaining 10 siblings (BC-5797–5805) can fan out in parallel with high confidence.

**Secondary observation: pre-merge review IS the compound-engineering instrument that makes revert+reship (BC-5795) rare.** BC-5795's revert+reship protocol was expensive — ~25 minutes agent time from P1 confirmation to merged fix, plus the revert commit left in history as an audit marker. BC-5796's pre-merge review cost ~5 minutes of reviewer time + 3 one-line edits. The compound-engineering principle here: every precedent about post-failure recovery (revert+reship) should have a paired precedent about pre-failure prevention (pre-merge review). BC-5796 is that paired precedent for BC-5795.

**Tertiary observation: factual-anchor-discipline citations at Plan don't cover all factual risks.** The BC-5796 plan explicitly cited "factual claims verified via `gh api` fetch of brite-salesforce main on 2026-04-20" — yet the 22→20 bullet-count error slipped through anyway because line-range citation and bullet-count verification are separate disciplines. Lines were checked; bullets were not counted. Pre-merge reviewer caught it by running his own `gh api | sed -n '175,196p' | grep -c "^- \*\*"` — a check worth adding to the factual-anchor recipe for future customizations where bullet counts or item counts appear as load-bearing numbers.

**Quaternary observation: rebase-before-first-commit on long sessions.** The worktree was created at `origin/main = 4623921` at session start. By ship time, `origin/main = 6d5118c` (BC-5762 + its compound-learnings PR merged mid-session). `git diff main` inside the worktree showed a 605-line spurious deletion diff from the cadence refactor. Rebase onto fresh `origin/main` (stash → reset --hard origin/main → pop) was conflict-free because the diff was isolated to `plugins/revops/skills/sf-apex/SKILL.md`. Worth capturing as a process note: always refresh the worktree's view of `origin/main` before the first commit on sessions longer than ~1 hour; otherwise the PR diff shows the spurious deletions and blocks merge.

**Strengthens** BC-5794 (template validation) by adding "durable across three siblings" qualifier. **Refines** BC-5795 (revert+reship) by pairing it with pre-merge-review as the prevention instrument.
