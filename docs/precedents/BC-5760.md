# BC-5760: Cross-phase state-object schema drift caught by review, not by validate.sh

**Date:** 2026-04-20
**Category:** architecture
**Confidence:** 8/10

## Decision

When a multi-phase plugin shares state between phases (producer → consumer across a gate), the canonical state-object schema must live in **one** place — the entry command's `## Session State Object` section — and every phase that introduces new fields must update that schema in the same PR. validate.sh catches frontmatter errors but has no schema-drift detector; review agents (architecture-reviewer especially) are the safety net. Every future phase skill (BC-5761 housekeeping, BC-5762 narrative) should open its implementation PR with a weekly.md schema diff before writing the skill body.

## Context

BC-5760 implemented Phase 2 of `/cadence:weekly` — a per-project interactive interview skill. The skill introduced 7 new per-project state fields (`scope_decisions`, `overrides`, `skip_log`, `scope_confirmed`, `_fetched_issues`, etc.) and 5 cross-cutting fields (`bottleneck_warnings`, `bottleneck_threshold`, `weekly_planning_root`, `checkpoint_path`, `_scoped_project_names`, `leadership_planning_notes`). The initial implementation declared each field inside the skill body's §1 Inputs, but did NOT update the canonical schema in `plugins/cadence/commands/weekly.md § Session State Object`.

Review surfaced two classes of drift:

1. **Consumer reads a field the producer never emits.** SKILL line 63 branched on `audit_card.project_status == "parked"`, but Phase 1's `project-audit` agent (BC-5759, already merged) enumerates exactly 9 audit-card fields — no `project_status`. The parked-project branch was dead code, and the canonical project status lives on `state.projects[i].status.type` from Phase 0.3's `list_projects` call. The fix was a one-line rename; the insight was that Phase 1's output contract (agent `## Output`) and Phase 2's input expectations (SKILL §1 Inputs) had drifted.

2. **Field-name mismatch against the state schema.** SKILL §6 checkpoint-path bash block and §8 cycle-change detection both referenced `state.cycle.current.title`. weekly.md's schema declares `cycle.current = {id, name, startsAt, endsAt}` — `title` is the field for `cycle.previous` only (Linear's `list_cycles` returns different shapes for current vs previous cycles). The skill would have read an undefined property at runtime — path resolution would produce `w<empty>-<date>/` and cycle-change detection would always miss.

Neither class was catchable by validate.sh (frontmatter-only). Both were caught by architecture-reviewer + code-reviewer in parallel, scoring 9/10 confidence. The review pass also caught a third drift — SQ2's "(Recommended)" default described brainstorming output "after the quality gate," but the gate runs in §5, AFTER SQ2 (§4). That's temporal-ordering drift, same category.

The root cause is that SKILL.md §1 Inputs was treated as the local state-object schema, diverging silently from weekly.md's canonical schema. The fix is structural: make weekly.md the single source of truth, update it every PR, and reference back to it from consumer skills.

## Alternatives Considered

1. **Keep the schema per-phase in each SKILL's §1 Inputs — easier to read in context.** Rejected. Splits the schema across N+1 files (one per phase + the entry command). Each phase must re-derive the consumer contract from its producer's agent prompt. In practice this session proved the drift is invisible without a dedicated reviewer pass — every future phase would hit the same class of bug.
2. **Move the canonical schema to `docs/designs/cadence-orchestration.md` (BC-5810).** Rejected. That doc is the locked design contract; adding live schema to it would make the design doc a moving target. weekly.md is already the runtime orchestrator and is edited per-phase anyway.
3. **Keep weekly.md as the canonical schema; every new phase PR must update it + reference back from the skill (chosen).** Update once-per-phase, enforced by a per-phase PR convention. Skill §1 Inputs becomes "what this phase reads/writes in state" with a pointer to weekly.md's schema for shape. If a phase needs a field the schema doesn't declare, that's a signal the producer contract is under-specified and should be addressed before writing the consumer.

## Outcome

2 commits on the BC-5760 branch — initial implementation (337→178 lines after review fixes) + fix commit addressing 1 P1 + 6 P2 findings. Weekly.md schema extended with all 12 new fields, per-field comment naming the owning phase. SKILL.md §6 checkpoint-path resolution rewritten with pre-extracted variables (removing the printf-with-prose-placeholder pattern). §2 pre-loop section added consolidating resume-parse + backlog enrichment (reducing N checkpoint-file reads to 1). PR #140 opened at https://github.com/Brite-Nites/brite-claude-plugins/pull/140.

**Reusable beyond this case.** Every future phase skill in the Cadence plugin (BC-5761 housekeeping, BC-5762 narrative) should open with a `weekly.md` schema diff *before* the skill body. Every future multi-phase plugin (RevOps dogfood, any future agent platform) should adopt the same "one canonical state schema per command" convention. The architecture-reviewer is the designated catcher for this class of bug — confirmed in session, and the boundary-integrity framing in its prompt is the thing that worked.

**Secondary learning — the "printf with prose placeholder" anti-pattern.** Bash blocks inside skill markdown must use pseudocode framing with pre-extracted variables (`"$CYCLE_NN"`), never angle-bracket prose placeholders (`"<cycle_number_parsed_from_...>"`) as `printf` arguments. An executing agent may attempt literal execution and fail. Add a YYYY-MM-DD regex guard on any date component that flows into a filesystem path.

**Tertiary learning — the simplify-pass agents caught real bugs on markdown diffs.** 3 of the 17 simplify findings were high-confidence correctness wins (CQ3 self-contradiction, SQ2 ordering, printf placeholder) that would not have been obvious to a human code-reviewer looking only at "does the prose read well." The reuse/quality/efficiency framing surfaces LLM-at-runtime bugs that hide inside seemingly-valid specs. Don't skip simplify on NON-TRIVIAL markdown diffs.

**Strengthens** `feedback_more_checkins_for_infra_issues` — multi-phase plugin skills need a schema-check-in gate between skill draft and PR open.
