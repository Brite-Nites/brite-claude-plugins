## Task 1 — Override past-self deferral when the original reasoning was context-bound

**Date:** 2026-05-04
**Category:** pattern-choice
**Confidence:** 7/10
**Tags:** override-past-self, context-bound-deferral, plan-gate, issue-body-reframe, focused-session

### Decision

When an issue body explicitly says "don't do X right now" (e.g., a deferral pattern recorded across multiple rounds), pause at plan-gate and re-examine the original reasoning trace before honoring it. If the deferral rationale was **situational** (specific to a context that no longer applies — e.g., "inside a 5-hour walk-through where pre-poisoning is a context switch"), the present decision is whether to honor the past-self instruction or to revisit it under the current context. Surface the choice to the operator with the original rationale, the present-context rebuttal, and a recommendation. Do not silently override past-self; do not silently honor a context-bound deferral when the context has changed.

For BC-6545: the issue body said "Not a request to test F22 right now (the deferral rationale across 3 rounds is sound)" — the rationale was that pre-poisoning workspace 13 added setup-and-cleanup load not justified during 5-hour dogfood walks. In a focused session whose entire scope was BC-6545 (no main flow to protect), the 5-min walltime was just 5 min, and the test produced real signal that removed an unverified hedge from the spec. Initial recommendation was conservative (Option 1 — soften the wording, honor past-self). Operator pushback ("why would we not just go ahead and test this?") triggered the re-examination; reframe + recommendation flip landed on Option 2 (run the test). Outcome: F22 verified-as-spec with two nuance corrections (fires on draft campaigns too; `call_api` strips response body).

### Inputs

- Issue body § "What this issue is NOT" — explicit "Not a request to test F22 right now"
- Issue body § "Deferral history" — three-round table with rationale per round; round-2 + round-3 both cite "pre-poisoning adds setup-and-cleanup load not justified by F22's load-bearing-ness for the MVP launch path" — rationale is **inside-walk-specific**
- Issue body § "Why F22 isn't load-bearing" — argues no production driver (Brite doesn't run overlapping campaigns); valid for *urgency* but NOT for *cheap-test rejection*
- Operator pushback transcript: "why would we not just go ahead and test this?" — surfaced the situational nature of the original deferral
- Plan file fallback path explicitly accommodated activation-blocker pivot, which then produced the broader-than-expected verdict

### Alternatives Considered

1. **Honor past-self deferral, soften the spec wording (Option 1)** *(initially recommended)* — adds "(unverified — see BC-6545)" caveat to 3 spec lines, closes BC-6545. Conservative, ~30 min, no override of issue-body guidance. **Rejected** at operator pushback — leaves an enshrined claim hedged but still unverified, costing future readers a re-derivation if anyone wants the actual answer.
2. **Run the test, override past-self (Option 2)** *(chosen)* — pre-poison workspace 13 with throwaway campaigns + lead, attach + observe, record verbatim, update spec with verified behavior. ~45 min including teardown. Removes the hedge permanently. Contradicts issue-body guidance, but the contradiction is justified by the context shift (focused session, no main flow).
3. **Memory-only, close as-is (Option 3)** — issue body itself is the deliverable, no code change. ~5 min. **Rejected** — leaves the launch-campaign.md unverified-assertion drift untouched (would need a separate ticket later); least useful per dollar of operator time.

### Promotion candidate

1st instance of explicit "override past-self when deferral rationale was context-bound" pattern. Promotion eligible at 2nd instance — when another deferred ticket is reopened in a focused-session context and the operator triggers the same diagnostic move. At that point, consider promoting to a check #11 in the writing-plans factual-anchor recipe family (or to a stand-alone rule in `workflows:brainstorming`): "When the issue body contains a deferral rationale, classify the rationale: situational vs structural. Situational rationales need a re-examination at plan-gate; structural rationales (no production driver, no operational pattern) can be honored without re-examination." Until then, keep as a per-issue judgment call, triggered by user prompt or operator pause.

Note on confidence: 7/10 not 8/10 because the "operator pushback flipped the recommendation" path is a specific dynamic that may or may not generalize. The pattern requires both (a) operator pause/question, AND (b) availability of a reframe that the agent didn't initially surface. If operators don't pause, the agent silently honors the context-bound deferral. Future occurrences should test whether this needs a proactive surface-the-rationale-classification step at plan-gate, even without operator prompting.
