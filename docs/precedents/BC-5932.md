## BC-5932 — 2026-04-23 — Two-offer preset split in a single vertical uses default filenames for the primary motion + `-{offer-name}` suffix variant filenames for the tactical complement

**Category:** pattern-choice
**Confidence:** 7/10

**Inputs:**

- `SKILL.md` § 3 lazy-load pattern: `presets/{preset}-{vertical}.md` — schema extends to `{preset}-{vertical}-{offer-name}.md` for variants without breaking the load path

**Alternatives Considered:**
1. **CHOSEN.** Primary offer uses default filenames (`list-building-zoos.md` / `risk-reversal-zoos.md`); tactical complement uses `-pilot-zone` suffix variant filenames (`list-building-zoos-pilot-zone.md` / `risk-reversal-zoos-pilot-zone.md`). 2. Put both offers in one file with section markers (`## Offer E` / `## Offer A` inside one `list-building-zoos.md`). Rejected — collapses the lazy-load contract. The skill reads one preset file per invocation, not section-parses a shared file. Multi-offer-per-file would require skill-side changes to SKILL.md § 3 lazy-load and JSON artifact schema.
3. Use subdirectories: `presets/zoos/list-building-offer-e.md` / `presets/zoos/list-building-offer-a.md`. Rejected — breaks the Glob pattern Municipalities uses; would require SKILL.md § 3 lazy-load rewrite. The filename-suffix approach is additive (old verticals keep their default filenames; new verticals can add suffix variants without touching the skill).
4. Use tier-name suffixes instead of offer-name: `list-building-zoos-t2.md` / `list-building-zoos-pilot-zone-t2.md`. Rejected — the tier is already implicit in the `list-building` / `risk-reversal` prefix (list-building = T1/T2, risk-reversal = T4). Suffixing with `t2` is redundant; suffixing with the offer name is the load-bearing differentiator.

## BC-5932 — 2026-04-23 — First-season-breakeven-or-no-pay linguistic pattern codifies the Offer E T4 risk-reversal shape; fee is not billed until a named revenue-stream baseline is met

**Category:** pattern-application
**Confidence:** 7/10

**Inputs:**
- BC-5879 zoos-ledger § A1 Hormozi mapping for Offer E: Effort + Sacrifice input = "venue near-zero capital, near-zero execution risk, operations limited to hosting"
- BC-5932 issue body Task 2: "Guarantee framing: first-season-breakeven-or-no-pay"
- `SKILL.md` § 8 anti-slop: "Avoid guarantee language that would require municipal legal review (e.g. 'refund in full', 'zero-cost until delivered'). Use outcome-based framing"
- BC-5825 Municipalities T4 precedent uses phase-gate guarantee ("if phase 1 doesn't deliver X by Y, phase 2 isn't billed") — same outcome-gated shape, different object (phases vs revenue streams)
- Nonprofit legal review constraint: zoos are typically 501(c)(3) — guarantee language cannot trigger contract-review cycles that delay signing past the Q3 sponsor-pipeline close window

**Alternatives Considered:**
1. **CHOSEN.** Body shape: "the production-finance fee is not billed until the program breaks even in year one against `{BASELINE_TERMS}`" where `{BASELINE_TERMS}` is operator-filled with the named revenue streams that count toward breakeven (attendance + sponsor inventory + ad revenue on pixel inventory). Step 2 bump expands the specificity: "gate-scan attendance revenue plus sponsor-inventory paid commitments plus ad-revenue pre-commits on pixel displays, measured against the production-finance fee at season close. If the math doesn't land, the fee isn't billed." Reason: (1) "fee is not billed" mirrors Municipalities phase-gate precedent ("phase 2 isn't billed") — legally safe at nonprofits because no money moved; (2) naming the revenue streams that count toward breakeven prevents sponsor-side rev-recognition ambiguity at accounting close; (3) the shape is operator-slottable — different venues will have different baselines (some have ad inventory ready, some don't; some have a pending title sponsor, some have three), and the `{BASELINE_TERMS}` placeholder is how the preset handles venue-specific revenue stacks without forking the file.
2. "Performance guarantee: if the program misses its attendance target, we refund half the fee." Rejected — "refund" triggers the nonprofit legal review trap SKILL.md § 8 names. Outcome-gated ("not billed until") avoids the trap.
3. "Satisfaction guarantee: if you're not happy with the program, we make it right." Rejected — vendor-speak, not venue-safe. "Satisfaction" isn't measurable; committee review would reject.
4. Tier-specific breakeven threshold ("break even on attendance alone" vs "break even on full revenue stack"). Rejected — the preset is not a contract; the `{BASELINE_TERMS}` placeholder lets the scoping call define tier. Preset body stays general; scoping call specifies.
5. No guarantee language at all — just state "revenue-share on net" from the ledger § A1. Rejected — misreads T4's purpose. T4 is the risk-reversal tier; revenue-share alone doesn't reverse risk (it shares upside, not downside). Breakeven guarantee is the downside reversal.

**Outcome:**

- Tests: 0 added, 0 passed, 0 failed (docs-only)
- Approved by: auto-verified (TRIVIAL triage; verified at write-time against nonprofit-legal-safe framing + BC-5825 phase-gate precedent)

## BC-5932 — 2026-04-23 — Offer A T4 dwell-time guarantee uses sensor-or-head-count measurement specificity + case-study-rights-void walk-away structure; NEVER photo-share

**Category:** pattern-application
**Confidence:** 7/10

**Inputs:**
- BC-5879 zoos-ledger § Offer A fix #2: "Swap backend guarantee metric. 'Photo-share benchmark' is gimmicky + disconnected from venue success. Replace with venue-native metric: dwell time in the pilot zone (sensor / head-count), attendance uplift in programmed hours (gate-scan data), or sponsor-visibility impressions"
- BC-5879 zoos-ledger § Offer A fix #3: "Reframe commercial structure. 'Install-at-cost for case-study footage rights' sounds supplicant. Rephrase: 'We'll underwrite the install cost. In exchange, we use the results in our sales material.' Confident, not asking a favor."
- BC-5932 issue body Task 4: "Guarantee metric: dwell-time / attendance-uplift / sponsor-visibility (pick one + name the metric)"
- Reviewer constraint: the guarantee must be committee-safe at venues where the incumbent lighting vendor is entrenched (Offer A surfaces there by definition)

**Alternatives Considered:**
1. **CHOSEN.** Pick dwell-time as the default primary metric named in Step 1 body ("if the zone doesn't hit `{DWELL_THRESHOLD}` dwell time measured by sensor or head-count"), with operator-switchable attendance-uplift or sponsor-visibility substitutes noted in the Step 1 explainer. Walk-away structure: "the case-study rights clause voids and you walk with the install and no obligation." Step 2 bump names the specific measurement method: "dwell time is counted by a pressure-sensor mat or an AI computer-vision pass on existing camera feeds, whichever is easier to install in `{PILOT_ZONE_AREA}`. The threshold is baselined against a comparable zone during the same hours the prior season, so the comparison is apples-to-apples." Reason: (1) dwell-time is the most broadly applicable venue-native metric (attendance-uplift requires gate-scan integration; sponsor-visibility requires sponsor branding on the pilot zone); (2) sensor-or-head-count gives the committee two measurement options — a sensor mat install (fast, low-cost) OR a computer-vision pass (no hardware, uses existing cameras); (3) the case-study-rights-void-and-walk-away structure matches the § Offer A fix #3 confident commercial framing — Brite keeps the risk, the venue keeps the install with no obligation, the reciprocity (case-study rights) is what Brite "buys" with the underwrite; (4) apples-to-apples prior-season baselining pre-empts the committee's most likely pushback ("how do we know the dwell-time target is fair?").
2. Lead with attendance-uplift as the default metric. Rejected — requires gate-scan integration which many mid-market venues don't have in a single pilot zone. Dwell-time works with a sensor mat or camera-feed computer-vision pass, both of which Brite can install itself.
3. Lead with sponsor-visibility impressions. Rejected — assumes sponsor branding is on the pilot zone, which is an Offer-E-primary assumption, not Offer A. Offer A is often the first zone Brite touches at a venue; sponsor branding is not necessarily there.
4. Photo-share metric (the original ledger-rejected framing). Rejected by the ledger and by the issue body; documented in the anti-slop bullet as the first "do not" rule so future regenerations don't drift back.
5. "Performance guarantee: if the pilot underperforms, we refund 50% of the underwrite." Rejected — the underwrite IS the refund mechanism (Brite underwrites the install cost; no refund to issue). The walk-away IS the guarantee. "Refund" language re-introduces the nonprofit-legal-review trap from BC-5825 / BC-5932 task-2.
