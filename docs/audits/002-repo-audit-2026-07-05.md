# Repository Audit — brite-claude-plugins (2026-07-05)

**Audited at:** `origin/main` @ `04d87b12` (2026-07-01), via a detached worktree.
**Method:** four-phase principal-engineer audit (discovery → evidence-based findings → strategy → task plan); three parallel deep-dive passes (scripts/CI, plugin structure/security, docs/tests); all High-severity claims independently re-verified against HEAD before publication.
**Relationship to prior work:** this audit was run independently of, and then reconciled against, the 2026-07-02 improve-skill deep audit (`plans/README.md` ledger + plans 001–005). See the Reconciliation section — do not file duplicate work from this document without checking that section first.

## Executive Summary

**Overall health: B−.** The enforcement machinery — CI gates, version-parity checks, secret handling, ADR governance — is genuinely excellent for a repo of this class, and the security sweep found zero hardcoded credentials anywhere (FACT). Three things drag the grade down: a meaningful slice of the test suite is decorative (26 Python contract-test files that no runner executes), the repo-level release bookkeeping is dead (broken `release.sh`, frozen `VERSION`, a CHANGELOG three months and five minor versions stale), and the front-door docs misrepresent the product (README describes 1 of 6 plugins and omits the "strongly recommended" core plugin entirely).

**Top 3 risks:** (1) false confidence from unwired tests — regressions in revops/marketing hook validators ship undetected; (2) `release.sh` would corrupt `marketplace.json` if its guard were bypassed, and the guard itself makes the script unrunnable; (3) the outbound skill template teaches the exact MCP-namespace pattern the repo's own docs warn silent-fails at runtime.

**Top 3 opportunities:** (1) wiring existing tests into CI is nearly free coverage — the tests are already written; (2) the repo already has the drift-lint pattern (clone-drift, agent-skills-drift) — pointing it at its own front-door docs closes the staleness class permanently; (3) consolidating the 6 verbatim copies of `gbrain-team-broker.sh` into the already-proven `plugins/_shared/` pattern removes the largest sync hazard.

No Critical-severity findings in this pass — note however that the 2026-07-02 audit's plan 001 (person-level contact data tracked in a public repo) is P1 and remains the single most urgent item across both audits.

## Repo Map

**Purpose.** Internal plugin monorepo for the Brite organization: Claude Code plugins implementing a structured engineering workflow (workflows), domain skills (marketing, revops), planning cadence (cadence), the Flow-Driven Architecture system (flow-architecture), and cross-cutting hooks/brain wiring (brite-core). Pure markdown/JSON content plus bash/python validation tooling — no build step, no runtime service.

**Stack.** Markdown skills/commands/agents + JSON manifests; ~153 shell scripts and ~156 Python scripts (linters, generators, test harnesses); GitHub Actions CI; Bitwarden-brokered secrets; Linear as issue tracker. 1,850 tracked files, 25 MB, first commit 2026-01-13, ~96 commits in June 2026 alone.

**Architecture sketch.** `.claude-plugin/marketplace.json` registers 6 plugins → each `plugins/<name>/` carries `.claude-plugin/plugin.json` (strict schema), auto-discovered `skills/`, `commands/`, `agents/`, `hooks/hooks.json`, `.mcp.json`. Enforcement flows through `scripts/validate.sh` (3,019 lines, ~40 numbered sections) invoked by `.github/workflows/validate-plugin.yml`, which layers required jobs (validate, vslice-greenfield, eval-gate) over six advisory jobs (drift checks, smoke tests, cross-PR ADR guard).

## Audit Report

### The ugly parts (highest priority, in order)

**U1 — A quarter of the test surface is decorative.** 26 `test_*.py` files under `plugins/{revops,marketing,workflows}/tests/` — including the entire revops hook-validator suite (`test_soql_validator.py`, `test_apex_validators.py`, `test_dispatcher_routing.py`, …) — are executed by nothing: no pytest job, no `validate.sh` reference, no workflow (verified: grep of `scripts/validate.sh` and `.github/workflows/*.yml` finds no runner). Several `.sh` harnesses are similarly orphaned (`plugins/core/tests/test_size_cap.sh`, all seven `plugins/workflows/scripts/test_build_*.sh`, `plugins/flow-architecture/scripts/test_build_audit_report.sh`). **High — FACT.** Consequence: the validators these tests cover can regress silently while CI stays green, and the tests themselves rot. → Remediation: `plans/003`.

**U2 — Release bookkeeping is dead, and the corpse is load-bearing-looking.** `release.sh` assumes one global version: it fails unless every `plugin.json` equals root `VERSION` (`scripts/release.sh:88-110`) — impossible now that plugins version independently (workflows 3.41.1 vs VERSION 3.29.0) — and its writer sets only `plugins[0].version` in marketplace.json (`release.sh:158`), which today is **brite-core**, so bypassing the guard would corrupt the registry. It also uses `mapfile` (`release.sh:78`), violating the repo's own carefully-maintained bash-3.2 discipline. `VERSION` is frozen at 2026-03-30 and consumed by nothing but `release.sh` itself. `CHANGELOG.md`'s last dated release is `3.29.0 - 2026-03-28` (`CHANGELOG.md:39`); workflows 3.37–3.41 and the entire flow-architecture plugin (269 files) have zero changelog entries. **High — FACT** (all verified directly). → Remediation: `plans/005` + DIR-2 decision.

**U3 — The front door lies.** `README.md:3` describes "A Process + Org plugin" (singular), claims "Current version: 3.24.0" (`README.md:5`), and its install snippet (`README.md:55-62`) installs only `["workflows"]` — omitting brite-core, which marketplace.json calls "Strongly recommended for all Brite team members" and which carries the security/brain hooks. `AUDIT.md` and `ROADMAP.md` are February fossils ("All 10 skills…" — `AUDIT.md:8` — vs ~70 skills today). README also references a nonexistent `scripts/format.sh` (`README.md:416`) and "BigQuery" (`README.md:33`) where Brite uses Snowflake. **High — FACT.** A new engineer following the README gets a broken, partial install. → Remediation: `plans/005` (extend to AUDIT/ROADMAP).

**U4 — The scaffolding template teaches a known-broken pattern.** `plugins/marketing/skills/_template/OUTBOUND-SKILL-TEMPLATE.md:5` sets `allowed-tools: mcp__plugin_marketing_emailbison-b2b__*` — a server not in `plugins/marketing/.mcp.json` (verified: servers are salesforce/spider/aiark/discolike/gbrain-team/enrichment), i.e., the exact silent-fail the repo's CLAUDE.md gotcha warns about. Worse, two shipped skills' *prose* asserts the broken form while their frontmatter correctly uses the short form (`email-bison/SKILL.md:65` vs `:5`; `campaign-orchestration/SKILL.md:75` vs `:6`) — a maintainer "fixing" frontmatter to match prose breaks the skill. Also stale: `plugins/flow-architecture/CLAUDE.md:67` claims the plugin's `.mcp.json` is "empty `{}`" — it now registers gbrain-team. **Medium/High — FACT. NEW in this audit.**

**U5 — Test debris is committed at repo root.** `bad.js`, `bad.py`, `bad.ts`, plus stub `package.json` (`{}`), `tsconfig.json` (`{}`), `pyproject.toml` (`[tool.ruff]`) are git-tracked at root (verified). They are fabricated by `scripts/test_precommit_advisory.sh:103-121`, which writes fixtures relative to CWD; they were swept in by commit `01e80db6` (2026-05-31). **Medium — FACT** (leak), **JUDGMENT** (non-hermetic harness is the root cause). The stub `pyproject.toml`/`tsconfig.json` can silently alter tool behavior repo-wide. **NEW in this audit.**

**U6 — `validate.sh` is a 3,019-line monolith.** Section names like `2b`, `2b'`, `2b''`, `2b'''`, `2b-ci`, `15a-bc-12617` signal accretion; it is the single point through which nearly all enforcement flows. It works today, but every new gate raises change-risk in a file nobody can hold in their head. **Medium — JUDGMENT** on risk; LOC is FACT. → ledger DEBT-2 (registration table) + TEST-04 (characterization fixtures).

## Improvement Strategy

**Theme 1: One versioning truth.** The repo *de facto* moved to per-plugin versioning; the repo-level layer (`VERSION`, `release.sh`, dated CHANGELOG, README version banner) died silently and now actively misleads. *Target:* per-plugin versioning is declared canonical; `release.sh` + `VERSION` are retired (or rewritten per-plugin); CHANGELOG either gets a per-plugin structure or an explicit pointer to PR history. *Principle:* a dead mechanism must be removed, not left looking authoritative. *(→ plans/005 + DIR-2.)*

**Theme 2: A test that doesn't run is worse than no test.** 26 Python files + ~10 shell harnesses assert nothing because nothing runs them, while sitting next to a CI system that runs 30+ other suites. *Target:* every file under any `tests/` dir is either executed in CI or deleted; a meta-lint (the repo's own favorite pattern) fails when a `test_*` file is unreferenced. *Principle:* enforcement parity — if it's worth writing, it's worth wiring. *(→ plans/002 + 003, extended by the .sh-harness and meta-lint items.)*

**Theme 3: Point the drift-lints at the front door.** The repo has mastered drift detection for clones, agent rosters, ADR numbers — but README/ARCHITECTURE/CHANGELOG drift is unguarded, and that's where every Documentation finding came from. *Target:* README lists all marketplace plugins (lint: marketplace names ⊆ README), version strings in README are generated or removed, template/prose contradictions fixed. *Principle:* docs that can drift will; automate the comparison, not the writing.

**Theme 4: Converge conventions across plugins.** Frontmatter shape, `allowed-tools` coverage, hook style, and the broker script all diverge per plugin. *Target:* one documented frontmatter contract with a validate.sh lint; broker single-sourced in `plugins/_shared/`. *Principle:* the monorepo's value is shared discipline; divergence is debt with 6× interest.

**Explicitly NOT recommending:** wholesale `validate.sh` decomposition (it works, is heavily change-protected, and a big-bang split risks more than it saves — DEBT-2's registration table is the right increment); a sweep of all 47 no-strict-mode scripts (fix only CI-path and credential-handling ones); making behavioral tests PR-blocking (the cost trade-off is sound); enterprise release tooling (this is an internal repo shipping via git+cache, not a published artifact); touching ADR gaps (already governed).

**"Done" signals:** CI fails on an unwired `test_*.py` file; `release.sh`/`VERSION` deleted or a documented per-plugin release path exists; README lists 6/6 plugins and its install snippet includes brite-core; zero High findings on re-audit; broker md5 exists at exactly one path; a new skill scaffolded from the template passes the allowed-tools cross-check.
