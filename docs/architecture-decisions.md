- [ADR-042: Skill frontmatter contract + `allowed-tools` coverage gate (R8)](../docs/decisions/042-skill-allowed-tools-mcp-coverage.md) — a skill whose body invokes an `mcp__…` tool must declare `allowed-tools` (least-privilege); pure knowledge/reference skills are exempt. Enforced as **R8** (skills-only, gate-tier) in the ADR-034 full-surface structural gate — a net-new rule outside the completed R2–R6 ratchet, with a non-silent `# lint:no-mcp-invocation <reason>` override. Commands + the `sf`-CLI Bash axis deferred to follow-ups (BC-16387)
- ADR-042 **amendments**: *2026-07-29 (BC-16865)* — R8 graduates to the command surface; the deferral's "some are only subagent tool-specs" premise did not survive triage (all 16 are genuine orchestrator invocations), so the mandate is identical on both surfaces, grandfathered forward-only. *2026-07-30 (BC-16866)* — the revops **Bash axis** classified: **12 drivers / 2 knowledge**, keyed on *who runs the command* — a driver's own SKILL.md body tells the agent to run something (`sf` or a bundled script) wherever the command text lives, **including transitively through a `references/` file its Reference Map links**, while a knowledge skill produces an artifact or delegates execution to a named sibling. Supersedes the first pass's fenced-code criterion, which said 5/9 because it measured where the command *text* sits rather than where the *imperative* sits (corroborated by `sf-connected-apps`, the only skill already declaring `allowed-tools`, which the old test called knowledge). Both the original criterion error and two later under-counts were caught by adversarial review, always in the same direction — reference-reachable scripts are invisible to a `SKILL.md` skim. Two axes are tracked because they diverge: `sf-docs` executes but never reaches an org, while `sf-permissions` and `sf-integration` **mutate** one. Three traps for the hardening pass: `Bash(sf:*)` is insufficient (5 drivers run bundled `deploy.sh`/`cli.py`/`*.sh`/Python), executing ≠ org access, and unwired `hooks/scripts/**` (8 skills, 32 files) is not evidence of execution — reachability from the body is. The frontmatter change stays split out as dogfood-gated work (BC-17743) — **no gate in this repo can verify an `allowed-tools` restriction**, so an under-enumeration fails at agent runtime on the deploy path
- [ADR-043: Python lint gate — ruff, bug-rules-only, grandfathered per file](../docs/decisions/043-ruff-python-lint-gate.md) — restores the Python lint gate the repo lost when BC-16371 deleted the leaked root `pyproject.toml` stub the local pre-commit ruff keyed on. Config in a real root `pyproject.toml` carrying `[tool.ruff]` and deliberately no `[project]`/`[build-system]`; `select = ["E9","F"]` (syntax + pyflakes — 130 findings, vs 1252 for a broad set); today's findings grandfathered per-file/per-code so the gate is green day one with zero code churn and **zero plugin version bumps** (51 of 54 debt files sit under `plugins/*/skills/**`, where any edit forces a bump). Enforced by a dedicated blocking `python-lint` CI job with a pinned ruff — NOT a `validate.sh` section, which is deliberately stdlib-only/no-pip and would make the gate a silent no-op. Debt burn-down is a separate per-plugin ticket (BC-16867)
